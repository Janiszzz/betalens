# Betalens DB Manager

独立运行的多来源数据库管理组件，不依赖 Betalens 的研究、因子或回测代码。

```bash
python -m pip install -e './betalens-db-manager[files]'
betalens-db-manager serve
```

浏览器访问 <http://127.0.0.1:8010>。从“本地表与配置”填写数据库和来源鉴权，再按 PostgreSQL、ClickHouse 多选表，预览并确认一键补建缺失结构。检查只查询系统目录，不扫描业务数据；已有结构不符只报告。现有私有环境文件可通过 `--env /private/credentials.env` 继续使用，现有任务、归档和数据不会搬移。

六个页面为“本地表与配置” `/tables`、“更新与审计” `/updates`、“任务清单与回退” `/tasks`、“业务完整性” `/integrity`、“字段映射” `/mappings`、“订阅源” `/sources`。支持刷新、深链接及前进/后退。多表请求创建后跳转 `/tasks?task=<id>`，点击启动后才下载。旧 `/settings`、`/tasks?table=…`、`/schedules` 链接会转向新入口。

配置目录自动生成 `schema-manifest.yaml`，汇总业务 YAML、原生管理/审计合同和参考域结构。批量建表自动加入依赖，确认绑定清单版本、连接目标及结构快照，只创建缺失表及索引。手工表定义、迁移和归档入口收在“高级管理”。凭据另存新位置保留原文件和当前运行配置，网页给出重启命令；不会搬移 SQLite、任务或归档。

默认配置目录为 Linux/WSL `~/.config/betalens/db-manager/` 或 Windows `%LOCALAPPDATA%\Betalens\DBManager\config\`；状态和缓存分别位于 Linux `~/.local/share/betalens-db-manager/` 或 Windows 同级 `state` 目录。凭据禁止写入任意 Git 工作树；Linux 文件权限为 `0600`，Windows 使用受限 ACL。

新建网页任务默认使用异步后台管线：预览 API 请求 → 创建任务 → 显式启动采集 → 原始归档与轻量检查 → 独立转换 → PG/CH 各自批量写入和存储核验。关闭网页后已启动的后台任务继续；服务重启后须显式恢复。旧任务继续使用原有下载、预览和确认语义。

任务完成后存在待审计拒收批次，网页会自动进入 `/tasks/review?task=<id>`；也可从任务详情点击“人工审计拒收批次”。清单按状态筛选和分页，逐批查看拒收样例、原始归档、字段合同及合格缓存。每个浏览器会话对同一任务自动跳转一次，返回详情后不会反复跳转。

人工审计支持“确认放行”“拒绝并导出元信息”“手工修补后导入”。通常放行现有合格缓存；来源覆盖不足时，需明确勾选接受现有覆盖，才会在独立受限进程中从原归档重新转换并预览合格记录。该选择只接受缺失请求、覆盖不足等范围异常，文件哈希、响应字段、日期和证券范围检查继续执行；原完整性异常保留，人工放行记录带有明确质量标记。空主键和非法类型仍需修补。修补使用 JSON 本地表记录，支持下载字段模板、上传文件或直接编辑；可按业务主键补充字段，系统审计字段自动生成。所有操作记录说明，原拒收与归档保留。写入前预览原任务目标库中的实际差异，确认后后台执行，保留预览前值检查、物理结构检查及双库独立结果。人工写入回执归入原任务，可随原任务回退。失败可重试原决定，或重新审计；拒绝后自动下载 JSON 元信息。运行中的主任务只允许查看，结束或停止后才能提交决定。

请求与批次进度使用固定任务总量：规划阶段先取得完整证券清单和交易日历，冻结逻辑请求范围与转换批次数。一个逻辑请求覆盖它的全部分页/拆分后继，追加归档分片另计，不增加进度分母。明确失败及拒收计入“已处理”，同时单列异常数、通过数和拒收未写数。旧的已结束任务按最终归档与处理批次冻结总量，刷新页面保持一致；未能取得完整范围时显示“正在规划”，不提供虚假的总数。人工审计结果单独显示，不改变原任务总量。

“更新与审计”支持为每次任务设置 Tushare 每分钟请求次数；新管线按已确认的 5000 积分档规划，共享总上限默认 450 次/分钟；接口更低限制优先。旧版任务留空仍使用私有配置的 `TUSHARE_RPM`。预览表展示每个接口的实际限频、单次行数上限及获取策略；例如 `stock_basic` 另受官方 50 次/分钟限制。HTTP 429 遵守 `Retry-After`，分钟限频会暂停后重试，日/小时配额不足保留检查点并停止。

支持偏移分页的查询按实际返回行数推进，持续请求至空页，短页不会直接终止；重复或交叠页阻止提交。非分页查询达到已登记上限后，按不重叠日期范围、证券或文档登记的枚举条件拆分；证券分区使用重新从来源获取并归档的完整基础清单，不以本地残缺清单代替。父响应仅作审计证据，不重复入库。最小范围仍触及上限或无法证明分区完整时，任务明确阻断。每页及分区保存检查点，恢复时复用经哈希核验的归档；预览中的“请求分片与获取完整性”展示结果。规则针对已登记的 31 个接口，不承诺源端未披露或未返回的数据本身完整。

新建任务的 `fund_share`、`fund_nav`、全市场 `index_daily` 使用已实测推进的分页；净值按自然日和 E/O 市场查询，避免逐基金展开，页大小分别请求 2000、10000、8000 行。页大小与官方公布的行数上限分开展示。显式证券范围中，已验证支持多代码的 `daily`、`adj_factor`、`fund_share` 按日期跨度和响应上限打包；其他接口保留原证券范围，不能用未经验证的逗号代码或改变日期含义来缩减请求。同一接口、参数和合同的业务/依赖查询共用原始响应。基础清单严格沿对应市场分区的归档链收集，单次异常回退超过 2000 个证券请求时阻断。必须逐证券获取的历史请求，每 100 组证券查询合并为本地转换批次；这不会改变网络接口的限制。请求预览显示运行时展开预算，不把初始请求数当作总请求数。

“任务清单与回退 → 缓存与写入审计 → 优化请求并建立关联任务”调用 `POST /api/tasks/{id}/replan`。先停止原任务并等待退出；新任务保持原表、日期、证券、目标库和写入策略，冻结新获取规则，仅复用参数、来源合同、分页规则一致且哈希检查通过的归档。原任务及归档保留，旧任务恢复继续采用原冻结规则。接口只创建关联任务，仍需点击启动；不迁移已写入的批次回执或修改原任务计划。

- 表定义位于 `tables/<table_id>.yaml`；映射位于 `mappings/<table_id>.yaml`。网页编辑和直接编辑使用同一校验逻辑；修改 YAML 不会自动执行 DDL。
- 字段映射页通过下拉多选添加/移除 API 查询源，关系图展示各源到本地表的字段连线。普通字段在单个查询内一一对应；多个查询源使用完整业务主键（支持联合键）合并。共同键允许共享，重复业务列须显式选择主备优先级；同源同键存在不同记录会阻止写入。
- 新建手工表的映射使用 `format_version: 2`：每个绑定用 `join_keys: [{source_field: ticker, column: code}, {source_field: day, column: business_date}]` 记录共同键，并同时保留对应的 `fields` 连线。未使用的源字段在绑定的 `ignored_fields` 中填写原因；不完整规则可保存为草稿，但不能发起更新。旧版内置派生规则继续兼容。
- PostgreSQL 与 ClickHouse 是独立目标，默认全选；单库错误有独立结果。实际入库时间与源业务日期、实际可得时间、下载时间分别保存。
- 内置业务表覆盖已登记 Tushare 接口的输出字段。字段去向登记与实际验证分开报告；空响应、缺权限不代表数据完整。
- Tushare 只是来源之一。支持注册其他 HTTP API 和 Python 适配器（`SubscriptionAdapter` + `FetchContext`）；本地 CSV/XLSX/Parquet 可通过显式映射导入，Wind 未配置时明确报告不可用。
- 后台执行器每次操作使用独立子进程；新管线默认 8 个下载线程、2 个转换进程、两库各 1 个写入通道。旧版前台任务在最后一个管理页面关闭后停止，新管线显式后台任务继续。自动更新功能已移除：升级禁用旧计划、取消尚未执行的调度操作，保留历史及正在执行的任务；旧调度 API 返回 HTTP 410。
- SQLite 保存阶段、租约、批次清单与同步水位；原始归档、类型化 Parquet 和精确前后镜像固定保留，新管线不参加七天缓存清理。两库仅同步小型批次清单，分页审计按需展开镜像。回退检查当前值，保护后续任务修改。
- ClickHouse 查重将最多 5 万个键以 Arrow 临时键表上传，批量 JOIN 读取现值；键表随查询释放。仅当分区日期本身属于业务键时直接裁剪分区，否则先从键列确认实际分区，避免漏掉跨分区旧版本。提交前再次检查固定前提，写后合并核验键数量与全部字段。
- 每个目标写入队列可将最多 16 个待写转换批次中的同表、无重叠键数据合并，服从任务冻结的行数、字节数和最长等待时间；重叠键形成顺序屏障。原始批次编号、前后镜像、回执与固定进度总量保持独立。准备清单在业务写入前批量持久化并同步；完成回执批量确认，结束或失败时补同步。日志记录每次合并的批次数、行数及查重、准备、提交耗时。

`serve` 持续监护所属 worker，异常退出后退避重启；SQLite 临时锁冲突只重试控制操作，不重放业务提交。中断中的操作保留检查点，须显式恢复；已取消任务保持停止。字段映射按短事务批量登记，序列化和目标范围解析在持写锁之前完成。`GET /api/worker-status` 返回心跳、进程与重启状态。

任务清单按状态、目标库、表和编号分页筛选，只读取控制元数据；实时日志只订阅当前任务，首次打开、断线重连和页面唤醒时直接读取最新 500 条，按 ID 去重并实时追加，不逐页追赶历史积压。连接长期无响应时自动重连，HTTP 轮询也读取最新日志；完整历史仍保存在后台，旧 `after` 游标查询保持兼容。北京时间展示阶段和请求结果。冻结参数、缓存、写入审计、追加校验分别展开；参考域任务显示发布与撤销摘要，并链接原业务完整性流程。

管理器网页接口繁忙时，可另开独立只读监控：`python -m betalens_db_manager --env /private/credentials.env monitor --port 8011`，访问 `http://localhost:8011/tasks?task=TASK_ID`。它直接以只读连接访问控制元数据，每 3 秒刷新固定任务进度及最新 500 条日志；不初始化状态、不启动 worker、不提供任务或数据库写入接口。关闭监控页或监控进程不会停止导入。

CLI 与网页共用执行器。请求文件设置 `pipeline_version: 2` 后，用 `run JOB` 显式启动后台采集；`validate JOB --rules values relations readback` 追加只读校验。新入口 `POST /api/tasks/{job}/start`、`POST /api/tasks/{job}/validations`；校验支持表、证券、日期和目标库筛选，报告支持分页及 JSON 导出。默认只开 L0 包完整性与必要写入保障；L1 业务值、L2 关系、L3 完整读回及来源核验可独立勾选。未知依据不判通过，管理器后续写入使已有报告过期。旧版 `download`/`preview`/`commit` 继续需要原有确认。选择 `auto_commit: false` 时，新管线先生成缓存，再通过 `POST /api/tasks/{job}/pipeline/commit` 显式提交。

历史基金代码保留源端的 `!` 标识，不与去掉标识后的代码合并。股票 `daily` 与 `daily_basic` 收盘价四舍五入到两位小数相同时，允许精度差异并采用 `daily` 的价格；其他值差异及目标库读回、回退核验仍精确比较。`fund_nav.ann_date` 可以为空或未返回，未知公告日期和可得时间保留空值，净值版本冲突仍独立检查。下载器在来源内部重试耗尽后，再按 5 秒、30 秒执行两轮自动重试，每轮仍受原限频控制；权限、配额和字段合同错误不按网络错误重试。缺失的归档文件会补拉对应请求，成功页继续复用，哈希损坏仍报告完整性错误。转换缓存包含规则版本，旧规则产生的拒收缓存不会直接复用。
