## 第 17 课：沿着数据流读源码

**目标与原理。** 阅读大型项目不必从第一行读到最后一行。先回答“我手里是什么数据，下一步交给谁，会得到什么”，再定位相关函数。

以 ALPHA101 为例，阅读顺序是：完整 YAML → `factor_ALPHA101.py` 的 `build_spec` 和 `run_from_config` → 类模板 → 通用 `FactorPipeline.run` → 分组函数 → `BacktestBase` → `Analyst`。

**例子。** `FactorSpec` 像实验说明书，`FactorPipeline` 像执行实验的负责人，`RunResult` 是装着回测、报告和诊断的结果包。`compute` 不一定立即执行；把函数放入 spec，相当于告诉管线“到计算阶段时用这个公式”。

**操作。** 用编辑器搜索以下名字，给每一步写一行输入输出：

| 名字 | 主要输入 | 主要输出 |
| --- | --- | --- |
| `load_yaml_config` | YAML 文件 | 配置字典 |
| `factor_spec_options` | 配置字典 | FactorSpec 参数 |
| `run_parameters` | 配置及文件位置 | 运行参数、解析后的路径 |
| `compute_momentum` 或已有算子 | 日期×股票宽表 | 因子宽表 |
| `single_characteristic` | 因子长表 | 带标签长表 |
| `get_single_factor_weight` | 标签 | 权重宽表 |
| `BacktestBase` | 权重、价格与状态 | 实际持仓、净值与审计 |

可在根目录使用 `rg -n "def run|class FactorSpec" betalens-factor/factor_template.py` 定位。`def` 声明函数，`class` 定义对象类型，`return` 把结果交还调用者。`if __name__ == "__main__"` 使命令行入口只在直接运行脚本时启动。

**练习。** 找出相对输出路径在哪里解析、整数手在哪里截断、权重时间在哪里加 10 分钟。不要只找注释，阅读真正使用参数的语句。

**验收。** 能解释“字段存在”不等于“执行路径使用了它”；能拿着结果中的异常，定位该看取数、公式、权重还是引擎。

## 第 18 课：添加自己的完整因子

**目标与原理。** 新增因子需要公式、完整参数和发现规则。课程提供完整的 COURSE_MOM，不需要自己拼接口。模板默认是 20 行回看动量、周频、五组、高低组多空，不开启行业或市值中性化，也不读取基准；这些是教学基线，不是选定的最优设定。

**操作一：离线读与检查。** 打开 `templates/research/COURSE_MOM` 内的 `.py` 和 `.yaml`。先运行帮助，不会查库或启动回测：

```powershell
python docs/learning/templates/research/COURSE_MOM/factor_COURSE_MOM.py --help
```

`inputs.close_wide` 对应数据库 `收盘价(元)`；`compute_kwargs.window` 传给算子；`build_spec` 按 window 同步历史需求；`run_from_config` 创建输出目录后才运行完整管线。

**操作二：有数据后运行模板。** 修改 YAML 中的研究日期与输出目录，再执行：

```powershell
python docs/learning/templates/research/COURSE_MOM/factor_COURSE_MOM.py --config docs/learning/templates/research/COURSE_MOM/factor_COURSE_MOM.yaml
```

它仍需交易日历、收盘行情、PIT 成分和交易状态。模板日期不保证你的库有数据。默认 `mask_inputs_by_pit: false` 允许对成分并集读取入选前的历史价格，再在信号日按 PIT 成分筛选；这对个股历史动量与每一天先掩码再计算是不同设定。

**操作三：让 Dashboard 发现。** 确认目标 `betalens-factor/research` 尚不存在，复制整个课程 research 文件夹：

```powershell
Test-Path betalens-factor/research
# 上一步为 False 时使用，避免覆盖自己的已有研究目录。
Copy-Item -LiteralPath docs/learning/templates/research -Destination betalens-factor/research -Recurse
```

复制后应该有 `research/class_research.yaml`、`research/COURSE_MOM/factor_COURSE_MOM.py` 和同名 YAML。若已存在 research 目录，先选一个未占用类名并同步修改 meta.class 与类文件名，不覆盖已有文件。重启后端或使用因子刷新接口重新发现。

**练习。** 将窗口改为 10，并换一个输出目录。证明你改动了公式参数，同时解释历史需求为何随之变化。再将空头组设为 `[]` 形成高分单多，注明它是另一种组合定义。

**验收。** import 不启动回测；脚本暴露 `spec`、`FactorPipeline`、`build_spec`；公式可手算，真实运行产物可追溯。课程只验证模板加载、配置和算子，未替你完成市场回测。

## 第 19 课：控制变量和样本外实验

**目标与原理。** 每次改变一个要素，才能判断结果差异可能来自哪里。先在探索区间选规则，再锁定规则去验证区间；最后保留独立测试区间。看过测试结果再修改规则，就把测试集变成了开发资料。

**例子。** 同时把窗口 20 改 60、周频改日频、五组改十组，收益变好后无法知道是哪项造成。更清楚的实验矩阵如下：

| 实验 | 窗口 | 调仓 | 组数 | 行业中性化 |
| --- | --- | --- | --- | --- |
| A 基线 | 20 | W | 5 | 关闭 |
| B 窗口 | 10 | W | 5 | 关闭 |
| C 窗口 | 40 | W | 5 | 关闭 |
| D 频率 | 20 | M | 5 | 关闭 |
| E 行业 | 20 | W | 5 | 开启 |

E 还会触发通用预处理路径，不能不加说明地把 A/E 全部差异都归因于行业残差；要严格拆分，需另行保持去极值和标准化流程一致。

**操作。** 先在实验记录中登记矩阵、研究区间和评价标准，再分别复制完整 YAML，使用独立目录运行。比较覆盖率、持仓、换手、回撤、分年度表现及收益，不只按收益排序。

**时间划分。** 比如使用最早一段开发、中间一段验证、最后一段测试，具体日期随数据覆盖设定。持有期跨越划分边界的标签会污染隔离；应剔除跨界标签或明确设置隔离间隔。使用测试期之前的历史价格作滚动预热本身不等于泄漏，关键是有没有用测试期结果拟合或挑选规则。

**练习。** 预写“什么结果会让我否定假设”，例如覆盖不足、收益完全集中于少数样本、不同年份方向不稳。不要把示例阈值当作所有研究的统一标准。

**验收。** 能提供运行前的实验矩阵和运行后的完整结果，包含失败或不理想的方案；独立测试期没有参与选择。

## 第 20 课：排错与让别人重跑

**目标与原理。** 排错从最小输入开始：环境 → 连接 → 数据 → 公式 → 分组 → 权重 → 成交 → 报告。一遇到错误就修改大量参数，会破坏因果定位。

**例子。** “六只股票无法分十组”是有效样本不足，不是依赖坏了；“No module named prettytable”是环境依赖问题，不是数据库空了；“报告写不出来”不一定表示回测没有完成，要区分阶段。

**操作。** 从 traceback 最后几行找异常类型与信息，再往上找自己的调用位置。把输入缩成一个月、少数代码，核对每阶段的 `.shape`、`.head()`、空值和日期范围。不要在错误发生后先删缓存、重装所有软件。

记录版本：

```powershell
git rev-parse HEAD
git status --short
python -c "import sys; print(sys.executable); print(sys.version)"
python -m pip freeze
```

Git 提交号不能代表未提交改动，故还需记录工作区变化；配置相同也不能代表数据相同，需记录数据来源、导入批次或快照。共享记录前去掉连接凭据；课程模板不要求填写密码。

**练习。** 用自己的语言重写第 11 课报错的原因和修复方法，再写一份“新开终端后如何重跑”的说明，包括目录、解释器、配置、数据条件、命令和输出路径。

**验收。** 另一人不依赖聊天历史即可重跑；失败有日志，成功有指标和底表，已知执行限制没有遗漏。无法提供真实数据的项目可以共享结构和演算，但必须标记复现范围。

**阶段作业。** 提交一个自定义因子、一份预登记实验矩阵和复现说明。检查 [逐课答案](练习答案与验收.md) 后再进入进阶模块。
