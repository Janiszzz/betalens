## 第 21 课：截面研究与择时研究

**目标与原理。** 截面研究比较同一天不同股票；择时研究判断某个标的在不同时点如何持仓。一个截面因子的绝对值，不一定直接具有跨时间可比性，需要明确历史阈值与信号规则。

**例子。** 信号分数超过“此前四个值的均值 + 一倍标准差”时做空。此前四个值不包含当前观测，否则当前异常值会抬高自己的阈值。历史不足时应先等足样本，不应拿未来数据补阈值。

**操作。**

```powershell
python docs/learning/labs.py 21
```

读 `values.shift(1).rolling(4)`，观察分数突然升到 8 时触发，之后阈值如何变化。这个例子只计算信号，没有成交和净值，不等同于项目完整择时实现。

再打开 ALPHA101 的 `_timing.yaml` 与脚本。当前文档描述的默认逻辑使用过去 120 个有效因子观测、历史上轨、一倍标准差、满仓做空，并把执行请求时间放在信号时间之后 10 分钟。实际参数要看你运行的 YAML。

Alpha101 择时公式仍可能需要 PIT 截面排名上下文，不能只加载目标股票就认为得到同一个公式。框架会把目标股票加入计算截面；目标自身必要字段的起点可能让有效研究起点后移。

**练习。** 在纸上列出“数据、阈值、触发、目标仓位、实际成交”五列。将做空改成做多属于改变哪个环节？窗口不足时你会如何处理？

**验收。** 能区分分数高、触发阈值、目标为 -1 和实际可成交四件事。不能将“后十分钟请求执行”描述为“保证十分钟后成交”。

## 第 22 课：事件研究与窗口收益

**目标与原理。** 事件研究把不同日期发生的事件对齐到相对日 0，再比较事件前后表现。横轴的 -5、+5 应表示标准交易日，而不是自然日；缺行情应保留空缺，不把后一天挤到前一天。

**例子与离线操作。**

```powershell
python docs/learning/labs.py 22
```

事件甲两天 +10%、-10%，事件乙 -10%、+10%。各自累计收益均为 -1%，平均也是 -1%；但逐日平均收益都是 0，再复利得到 0%。这说明“平均累计收益”与“平均日收益构造的累计曲线”不总相同，读图前必须知道聚合顺序。

**真实操作。** 课程 `templates/course_events.csv` 有两条虚构事件，仅供格式练习。正式研究要用有来源、时点可核验的真实事件替换。Dashboard 只扫描 `betalens-factor/tools/eventstudy/` 当前层的 CSV/XLS/XLSX，不递归扫描子目录；文件至少需要 `date`，可有 `event` 和 `remark`。

使用自己的事件表时，可通过 Python：

```python
import pandas as pd
from betalens import Datafeed, EventStudy

frame = pd.read_csv("你的事件文件.csv")
frame["date"] = pd.to_datetime(frame["date"])
events = pd.Series(1, index=frame["date"])
feed = Datafeed("daily_market")
try:
    result = EventStudy(feed).analyze(
        events=events, code="000001.SZ", metric="收盘价(元)",
        window_before=5, window_after=10, holding_periods={"days": [1, 5, 10]},
    )
    print(result["event_count"])
    print(result["holding_stats"])
finally:
    feed.close()
```

这里假定文件每行都是事件；若有 event=0 的行，需要先筛选。代码、事件与行情覆盖必须实际匹配。缺少数据库时不要直接运行。

**时点解释。** 默认收盘时点为 15:00，盘前/盘中与盘后事件的 Day 0 处理不同；恰好边界时间需按当前实现核对。只有日期的事件会被读成零点，不能把盘后公告随意只保留日期。Day 0 当日涨跌幅可能含事件发生前的价格变化，不能全归因于事件。

**练习与验收。** 做一张事件来源表，检查重叠事件窗口与逐事件覆盖，区分描述性关联和因果解释。只有两个虚构事件不能用于显著性结论。

## 第 23 课：参数挖掘、选择偏差与稳健性

**目标与原理。** 搜索的作用是评估不同参数，不会凭空创造可预测性。尝试越多，即使全是噪声，也更容易找到样本内看起来优秀的候选。

**离线例子。**

```powershell
python docs/learning/labs.py 23
```

100 个候选均由真实均值为零的随机数生成。用前 60 行选平均收益冠军，再看后 60 行。固定种子仅用于课堂复现；某次留出收益可能为正也可能为负，不能把它视为普遍概率结论。

**项目操作。** 先阅读 `docs/guide/factor-mining.rst` 和某个已有因子的 `mining/parameter_space.yaml`、`performance.yaml`。先小规模审阅：限制为一个因子、少量参数和少数窗口；日期边界、候选数、并行资源和输出目录全部明确后，再考虑执行。当前入口是：

```python
from betalens.factor.mining import run_mining

# 两个路径必须指向你已经审阅的完整小规模配置。
result = run_mining("你的parameter_space.yaml", "你的performance.yaml")
```

QMC 改善范围覆盖，TPE 根据历史评价寻找更好的区域，Grid 做局部遍历，扰动检查邻域稳定性。这些仍会使用被评价的样本。当前 total 热力图汇总完整 evaluation.span，不能凭图名把它称为独立样本外证据。缓存快也不等于数据更新后仍可复用，需核对输入指纹。

**稳健性接口。** 项目提供 `RobustTest(fund=..., factor=...)`、`.neu()`、`.bootstrap_once(n_bootstraps=...)`。此处 fund 是命名收益 Series、factor 是按日期对齐的多列 DataFrame。源码会先联合删缺失，再使用上一行 factor 对下一行 fund；它不是自动执行同日多因子 Alpha 回归。删缺失后相邻行的时间间隔可能不同，必须检查。

`.neu()` 当前逐列做回归和残差处理，不能仅凭“稳健性”名字就当成已控制所有其他因子的联合回归。Bootstrap 重采样也需要检查与时间依赖是否适配。课程不把其输出当作已经验证的通用显著性保证，正式结论前应审阅统计设计；不要使用未核验的旧辅助入口替代上述明确方法。

**练习。** 写清你搜索哪些参数、最多试多少、在哪些日期选择、何时锁定、独立测试期是什么。解释为何“看测试集后换一个冠军”不再是独立验证。

**验收。** 保存全部候选与错误，而非只保留赢家；能区分局部参数稳定、跨时间稳定和真正独立验证。

## 第 24 课：毕业项目——完成一份可复核研究

**课题。** 使用 COURSE_MOM 或一个已理解的简单因子，回答一个明确问题。可选“历史动量的高低分差异是否稳定”，也可选“某类事件后是否存在一致的描述性表现”。首次毕业项目只做一条主线。

**操作步骤。**

1. 用模板写研究假设，预先定义反证条件。
2. 完成数据字典、质量和 PIT 检查，确定实际可用区间。
3. 划分探索、验证、独立测试，检查跨边界的持有期标签。
4. 在探索期跑基线，抽查因子值、权重、成交时点和三笔交易。
5. 按预先登记的有限矩阵做对照，记录全部结果和异常。
6. 锁定规则，再做验证及最终独立测试；若根据测试修改，明确改成新一轮探索。
7. 填写[毕业报告模板](templates/毕业报告模板.md)，附配置、版本、数据说明、日志和产物。

**必须交付。** 一份报告；完整运行配置；数据字典和质量记录；环境和代码版本；至少一份回测底表或事件窗口底表；手算复核；实验对照表；他人可执行的复现步骤。

**评分标准。**

| 项目 | 分值 | 合格表现 |
| --- | --- | --- |
| 假设与预先定义 | 15 | 变量、样本、比较与反证条件清楚 |
| 数据质量及 PIT | 20 | 覆盖、单位、历史成分和可知时点有证据 |
| 公式与时间对齐 | 20 | 至少一个手算值正确，无未解释的前视使用 |
| 执行与底表复核 | 15 | 抽查实际持仓、价格和交易，限制明确 |
| 评价与对照 | 15 | 指标口径一致，保留不理想结果，隔离测试 |
| 复现与报告 | 15 | 配置、版本、数据来源和运行方法完整 |

80 分可作为自学通过线；若存在未解释的未来数据、把虚构收益当实测、或别人无法定位运行配置，即使总分高也需补做。没有真实数据库时可以交“离线方法项目”，但不能声称已完成真实市场检验。

**最终验收。** 请另一位同事问你：“这个分数怎么算？当时知道吗？何时成交？现金为什么这么多？费用如何处理？换一个年份会怎样？我怎样重跑？”你能用保存的证据回答，而不只指着净值曲线，就完成了这门课。
