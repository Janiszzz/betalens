## 第 05 课：分清 Python、项目依赖与数据库服务

**目标与原理。** Python 是解释执行代码的程序；pandas、NumPy 是它使用的工具；PostgreSQL 是独立的数据服务；Node.js 用于浏览器前端开发服务器。它们不是同一个东西。`.venv` 让项目依赖与其他项目隔离。

**例子。** Anaconda Python 已安装 pandas，不表示另一个 `.venv` 中也有 pandas。在 A 环境执行安装、在 B 环境执行脚本，仍会出现 `No module named ...`。用 `python -m pip` 可以让安装跟随当前 Python。

**操作。** 先检查，记录输出：

```powershell
Set-Location D:\git_clone\betalens
python --version
python -c "import sys; print(sys.executable)"
python -m pip --version
node --version
Get-Service *postgres*
```

若新建项目环境，使用你选定版本的 Python 运行：

```powershell

.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[full]"
python -m pip check
python -c "import betalens; from betalens.analyst import Analyst; print('research imports OK')"
```

已有合适环境不用重复创建。项目文档提供 Python 3.11/3.12 路线；当前终端是 3.13.5，部分实验已可运行，但完整依赖兼容性要通过安装验收判断。本次确实发现完整 Analyst 导入缺 `prettytable`，所以只验证 `import betalens` 不够。

**练习。** 用一句话解释为什么“PostgreSQL 服务 Running”不能证明库里有行情。记录目前使用的解释器绝对路径。

**验收。** 能在同一环境中运行离线实验和完整研究 import；未达成的项明确记录，不把它误当数据错误。详细安装帮助见 `docs/getting-started/installation.rst`。

## 第 06 课：理解数据字典、标准表与导入

**目标与原理。** 数据字典回答每个字段表示什么、单位是什么、何时可知。数据库 schema 是存放数据的结构，建立结构不会产生行情。运行时 `daily_market` 等名字可以是兼容视图，不必手工向视图写入。

一条标准指标记录通常包含 `datetime/code/name/metric/value/unit`。例如“股票 A、某日 15:00、收盘价(元)、10.8、元”。真正导入时必须使用合法代码及适配器要求的列名。

**例子。** “成交量=100”若单位是手，与“100 股”差 100 倍；涨跌幅字段中的 3 若表示 3%，计算时用 0.03。价格、分红和复权因子的处理也要写清楚，不能只看列名像价格就混用。

**操作。** 若尚无配置，复制模板并编辑。已有本地配置不要覆盖；环境变量、用户级配置也可能优先生效。

```powershell
Copy-Item betalens\datafeed\config.example.json betalens\datafeed\config.local.json
notepad betalens\datafeed\config.local.json
python -m betalens_db_manager plan
```

核对目标与计划后，需要初始化时执行 `python -m betalens_db_manager init --yes`，再执行 `python -m betalens_db_manager verify`。打开 GUI：`python -m betalens_db_manager`。在 GUI 先预览文件、识别列、看拒绝行和冲突，再导入。

**练习。** 给 ALPHA101 制作数据清单：交易日历、四个价格指标、历史指数成分、交易状态、行业、基准。每项写来源、频率、单位、起止日期、时间戳语义。用你实际拥有的数据填写，未知处留待核验。

**验收。** 能区分“数据库连通”“结构核验通过”“研究数据覆盖完整”。能解释 `insert_only` 与 `upsert` 的区别：后者可能更新同键已有值，应先审阅冲突。

## 第 07 课：第一次取数与 PIT 历史样本

**目标与原理。** `Datafeed` 是只读取数层。先查询一只股票、一项指标、一个月；确认正确，再扩展全市场。PIT 表示按查询时点取当时生效的记录，避免把后来发生的信息带回历史。

**操作。** 把以下 Python 保存为自己的 `query_lesson.py`，替换为库内存在的股票和日期，再运行：

```python
from betalens.datafeed import Datafeed, get_absolute_trade_days

feed = Datafeed("daily_market")
try:
    prices = feed.query_time_range(
        codes=["000001.SZ"], start_date="2024-01-01",
        end_date="2024-01-31", metric="收盘价(元)",
    )
    print(prices.head())
    print("记录数：", len(prices))
finally:
    feed.close()

print(get_absolute_trade_days("2024-01-01", "2024-03-31", "M"))
```

这段代码需要真实数据库和本地交易日历。返回空表时先查代码、指标名和日期，不能直接改动回测逻辑。

**例子。** 指数在 6 月调入 B，3 月回测不应因为 B 在年末仍是成分而提前纳入。年度报告写着 12 月 31 日，不表示市场在当日已知道报告内容，应核验实际公开时间。

**练习。** 在成分变动前后分别查询一个指数的历史成分，用 `Datafeed("index_universe").get_index_universe_panel(index_code, dates)`，对比集合差异，并关闭连接。参数细节查 `docs/guide/datafeed.rst`。若当前库无历史成分，本题记为待补数据。

**验收。** 能解释 `time_tolerance` 单位为小时，不是天；能说清最近之前查询为何仍然依赖正确入库时点。能检查实际交易日而不是拿自然日替代。

## 第 08 课：先检查数据，再解释收益

**目标与原理。** 质量检查至少包括唯一键、类型、缺失、范围、单位与覆盖率。覆盖率的分母必须是你定义的候选样本数；不能将缺失股票先删掉，再声称覆盖率 100%。

**例子。** A 同一天有价格 10 和 10.1，B 缺失，C 价格为零。这不是三只有效股票。A 需要核对来源，B 缺失要解释，C 非正价格不能正常计算相对收益。取平均或补零不是通用修复办法。

**操作。**

```powershell
python docs/learning/labs.py 08
```

观察 `duplicated(..., keep=False)` 如何把同键冲突都展示出来，`isna()` 如何定位缺失。示例只在明确给定人工核验结果之后算覆盖率，结果为 2/3。

**练习。** 为自己的数据写一张检查单：每个指标有哪些代码、多少日期、多少缺失、重复键多少、最早和最晚时间。随机挑三条记录与源文件对照，检查价格单位和数据可知时间。

**验收。** 能举出“字段完整但时间戳错误”的例子；能解释为什么停牌不等于零价格、缺失收益不等于零收益。
