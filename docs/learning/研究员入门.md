# Betalens 研究员入门：从研究想法到可复核的结果

系统学习请从[24 课完整课程导航](课程导航.md)开始；本文保留为速查手册。原 `first_factor.py` 对应完整课程的第 04 课。

本文根据本地仓库在 2026-09-04 的说明文档与核心源码编写。示例股票、收益和数值演算均为教学数据，不代表实际研究结果。没有执行真实数据库回测。

## 1. 先理解你在用什么

Betalens 是一个 Python 量化研究框架，有浏览器工作台和数据库管理界面。你提出假设，例如“相对开盘更强的股票，未来会不会表现更好”，它帮助你把假设转化为可重复的历史实验。

研究主线是：原始数据 → 当时可用的股票池 → 因子值 → 预处理 → 分组 → 目标权重 → 模拟持仓和净值 → 评价报告。

三个容易混淆的概念：

- **因子值**：某天给某只股票打的分，例如 0.4。分数本身不是收益。
- **因子组合**：按打分规则选择和配置的股票，例如做多高分组、做空低分组。
- **因子收益**：该组合在后续持有期产生的收益。高分不保证未来上涨。

## 3. 不需要数据库的第一课

进入仓库根目录，在 PowerShell 执行：

```powershell
Set-Location D:\git_clone\betalens
python docs/learning/first_factor.py
```

本例使用本项目真实的 `single_characteristic` 和 `get_single_factor_weight`，其余数据均为内存中的虚构数据，不访问数据库，也不调用完整回测引擎。需要当前 Python 能导入 pandas 和 Betalens 所需模块；缺依赖时按下一节安装。

ALPHA101 的公式是：

```text
因子值 = (收盘价 - 开盘价) / (最高价 - 最低价 + 0.001)
```

例如开盘 10 元、收盘 10.8 元、最高 11 元、最低 9 元，因子值约为 0.400。它衡量当天开收盘变化相对于日内振幅的大小。分母里的 0.001 用于避免振幅为零时直接除零，不是收益率。

脚本生成六只股票，因子值从 A 到 F 递增，分三组：

| 组别 | 股票 | 权重 |
| --- | --- | --- |
| 低分组，标签 0 | A、B | 各 -0.5 |
| 中间组，标签 1 | C、D | 各 0 |
| 高分组，标签 2 | E、F | 各 +0.5 |

如果后续 A、B 分别下跌 2%、1%，E、F 分别上涨 3%、4%，组合单期收益为：

```text
(-0.5 × -2%) + (-0.5 × -1%) + (0.5 × 3%) + (0.5 × 4%) = 5%
```

这里股票多头合计 +1、空头合计 -1，总绝对股票敞口为 2。`cash=1` 是这一净资产记账方式的结果，不能解读为没有持仓。它是多空研究组合，不能直接当成普通满仓买入组合。

脚本最后打印 5% 和净值 1.05。这只是单期演算，没有整数手、费用、借券限制、停牌或价格匹配。把未来收益改成相反方向重跑，可以看到同样的因子分数也可能对应亏损。

| 数据 | 用途 |
| --- | --- |
| 本地 `trade_calendar` 数据集 | 找到周末、月末及前一交易日 |

## 7. 学会修改 YAML

可直接运行的原文件为 `betalens-factor/alpha101/ALPHA101/factor_ALPHA101.yaml`。第一次可在同目录复制为 `factor_ALPHA101_learning.yaml`，在副本中修改实验参数。

```powershell
Copy-Item betalens-factor\alpha101\ALPHA101\factor_ALPHA101.yaml betalens-factor\alpha101\ALPHA101\factor_ALPHA101_learning.yaml
notepad betalens-factor\alpha101\ALPHA101\factor_ALPHA101_learning.yaml
```

YAML 相当于实验参数表。用空格缩进，不能用 Tab；保留其余必需字段。下面只是待修改的 `run` 部分，不是完整配置：

```yaml
run:
  start_date: '2024-01-01'
  end_date: '2024-03-31'
  rebal_freq: W
  grouping_mode: equal_count
  n_quantiles: 5
  initial_amount: 100000000
  benchmark_code: 000906.SH
  include_profiling: true
  dump_excel: true
  warmup_days: null
  output_dir: outputs/runs/learning_01
```

日期只是示范，必须换成你的数据覆盖区间。然后执行：

```powershell
python betalens-factor/alpha101/ALPHA101/factor_ALPHA101.py --config betalens-factor/alpha101/ALPHA101/factor_ALPHA101_learning.yaml
```

`--config` 的意思是“使用这份参数文件”。`output_dir` 相对于 YAML 所在目录解析，因此本例输出在因子目录内的 `outputs/runs/learning_01`，不是仓库根目录。每次实验使用不同输出目录，避免混淆或覆盖同名报告。

| 字段 | 研究意义 |
| --- | --- |
| `meta` | 因子名字、来源、公式与假设说明 |
| `factor_spec.inputs` | 算子参数名与数据库指标名的对应关系 |
| `compute_kwargs` | 公式内部参数，例如窗口长度 |
| `index_code` | 在哪个历史成分股票池中做研究 |
| `use_industry`、`use_mktcap` | 是否控制行业或市值影响 |
| `weight.mode` | 选取哪些分组建立组合 |
| `rebal_freq` | D 日、W 周、M 月、Q 季、S 半年、Y 年 |
| `n_quantiles` | 每期分成多少组；不是选多少只股票 |
| `initial_amount` | 初始资金；整数手使资金大小可能影响结果 |
| `warmup_days` | 计算前额外读取的自然日；null 表示自动推断 |
| `include_profiling` | 是否生成因子体检 |
| `dump_excel` | 是否导出回测明细 |

特别注意当前代码中的方向设置：通用管线的 `classic-long-short` 固定做多最高组、做空最低组。虽然配置存在 `direction`，当前该路径没有用它翻转权重。要明确做多低分组，可使用完整 `weight` 部分：

```yaml
weight:
  mode: freeplay
  long_groups: [min]
  short_groups: [max]
  group_weights: {}
  intra_group_allocation: {}
```

只做多高分组则用 `long_groups: [max]`、`short_groups: []`。这会改变研究组合定义，要重新检查权重和结果。

## 8. 代码背后的研究原理

**宽表与长表。** 宽表以日期为行、股票代码为列，适合同时计算很多股票的滚动指标；长表以“日期、股票”为一条记录，适合分组和合并。`DataFrame` 就是 Python 中的表格，`Series` 可以理解为带标签的一列。

**PIT（当时可知）。** 研究 2020 年不能拿今天的指数成分倒推整个历史。项目能逐期查询当时生效的成分和行业；其正确性仍依赖入库生效时间正确。财报报告期结束日也不等于市场实际看到公告的日期。

**预热。** 研究从某年 1 月开始，20 日动量仍需要此前至少 20 个交易日。`warmup_days` 是自然日；公式历史需求常以交易日根数衡量，两者不能混为一谈。

**去极值。** 避免个别异常分数支配均值和标准差。**标准化**把同一天的分数转到可比较尺度。**中性化**用行业、市值等解释分数，拿剩下的部分重新分组。例如高分只是因为集中在某一行业，中性化后排序可能变化。当前通用管线在开启行业或市值中性化时才进入这一整段预处理，不应假设所有运行都默认完成全部处理。

**两种分组。** `equal_count` 优先保证人数均衡，标签从 0 开始；同分股票可能被按代码稳定拆到相邻组。`value` 不拆相同值，所以实际组数可能减少。有效股票只有 6 只时要求 10 个等额组会报错。

**时点。** 当前通用截面管线先选周期最后一个交易日，再取其前一交易日作为信号日；权重索引来自输入行情时间戳，加 10 分钟后向后找成交价。日线信号标成 15:00 且使用收盘价时，通常匹配下一个交易日收盘价。加 10 分钟不是“保证在 15:10 成交”，应核对 `actual_datetime`。只有日期、被错误标成零点的数据可能破坏原本的时间语义。

**整数手。** 默认一手 100 股。例如资产 100 万元，目标权重 1%，股价 30 元：目标 333.33 股，实际截断为 300 股，占资产 0.9%，余额归现金。报告应看 `actual_weight`，而不能只看目标 `weight`。

**价格与费用。** 当前核心回测类的 `ftc`、`ptc` 只见保存和导出，未见用于净值扣费；不能据此声称已模拟手续费。默认停牌模式 `to_cash` 是目标权重调整规则，不是现实中停牌可即时卖出的保证。复权、现金分红、融资融券和涨跌停等执行口径也需要结合数据与实现单独确认。

## 9. 怎样读报告

| 内容 | 先问什么 |
| --- | --- |
| 覆盖率、缺失值、异常值 | 每期实际给多少股票打了分？缺失是否集中在特定时期？ |
| 组数与组内人数 | 分组是否有意义？某组是不是只剩几只股票？ |
| 分组净值 | 高低组是否持续有差异，还是少量极端样本驱动？ |
| 组合净值 | 1 变成 1.2 表示累计约 20%，不是每年 20% |
| 年化收益 | 按持有时长折算的增长速度；短期年化可能很夸张 |
| 最大回撤 | 从历史高点到之后低点跌多少，例如 1.2 到 0.9 为 -25% |
| 夏普比率 | 平均超额收益相对于波动有多大；不是胜率 |
| 换手与持仓 | 收益是否依赖频繁换仓、集中暴露或小资金取整？ |
| 基准相对指标 | 收益是否主要来自市场整体上涨？ |
| IC/Rank IC | 当期分数与后续收益/收益排序是否相关？ |

IC 在统计模块中计算时，应把后续收益正确对齐到信号期。传入同日期的当日收益可能回答成另一个问题。一次 IC 为正、一次回测盈利或试出一个最优参数，都不等于样本外有效。

常见文件与对象：

- `ALPHA101_report.xlsx`：指标报告。
- `ALPHA101_dump.xlsx`：回测底表；检查 `actual_weight`、`actual_datetime`、`rebalance_log`、`nav` 等。
- `ALPHA101_profiling.xlsx`：体检和分组诊断。
- 通用 CLI 管线还输出静态 PNG；不要假设每次 CLI 运行自动生成 HTML。
- 需要交互 HTML 时，可对已有 Analyst 调用 `to_html(...)`；Dashboard 的下载状态以页面实际生成结果为准。

## 10. 从会操作到会写简单研究代码

先学四件事：`import` 是拿工具，`变量 = ...` 是给结果取名，`函数(参数)` 是让工具干活，`DataFrame` 是一张表。

第一个真实取数练习如下，代码与日期必须替换为库内有数据的值：

```python
from betalens.datafeed import Datafeed

feed = Datafeed("daily_market")
try:
    prices = feed.query_time_range(
        codes=["000001.SZ"],
        start_date="2024-01-01",
        end_date="2024-01-31",
        metric="收盘价(元)",
    )
    print(prices.head())
finally:
    feed.close()
```

`metric` 必须与库里的名字一致。`.head()` 看前几行，`finally` 保证查询结束后释放连接。

理解宽表后，可以读懂这样的动量算子：

```python
def compute_momentum(close_wide, window=20):
    return close_wide / close_wide.shift(window) - 1
```

`shift(20)` 是沿日期向后移 20 行，让当日价格和 20 行前的价格比较。若输入每行确实对应一个标准交易日，它就表示 20 个交易日前；缺交易日或错误填充会改变含义。该算子只是公式，要变成 Dashboard 中的因子，还需脚本、类级 YAML、完整因子 YAML 和配置接口，参考 `docs/guide/factor-pipeline.rst`。

## 11. 进阶功能和学习练习

截面研究回答“同一天买谁”；择时研究回答“同一个标的什么时候持有”。Alpha101 的 `_timing` 默认信号有自己的滚动阈值和做空口径，不能把截面参数原样解释为择时规则。

事件研究回答“事件发生前后通常如何变化”，窗口按标准交易日对齐。观察事件均值可以发现规律，但不能单独证明因果关系。稳健性模块提供正交化与 Bootstrap 等工具；参数挖掘可批量尝试设定，但仍需要训练、验证和独立样本外检验。

建议依次完成以下练习，每次只改一个变量：

1. 跑离线例子，手算 5%，解释为什么空头下跌带来正贡献。
2. 修改虚构未来收益，观察因子分数不变而组合结果改变。
3. 查询一只股票，确认字段、单位和时间戳。
4. 跑一次短区间 ALPHA101，找到参数文件、实际权重、成交时间和净值。
5. 对比周频和月频，同时记录换手、覆盖率和净值差异。
6. 对比行业中性化开关，解释它改变了什么假设。
7. 固定研究规则后，使用未参与选择参数的后续历史区间评价。

合格的研究记录至少写清：研究假设、代码版本、数据来源与版本、样本区间、历史股票池、信号时点、成交时点、公式参数、分组及权重、资金规模、价格与费用口径、输出目录、主要结论及尚未验证的问题。

## 12. 遇到问题先查哪里

| 现象 | 第一项检查 |
| --- | --- |
| `No module named ...` | 当前 Python 路径与依赖是否匹配 |
| `connection refused` | PostgreSQL 服务、主机与端口 |
| `password authentication failed` | 实际生效的配置来源、用户名和密码 |
| 表不存在 | 连错数据库还是尚未初始化结构 |
| 日历或行情为空 | 是否导入、日期和 metric 是否匹配 |
| 股票池为空 | 历史成分、生效日期和状态锚点是否齐全 |
| 无法分成指定组数 | 有效股票数是否少于分组数 |
| 净值几乎不动 | 现金占比、整数手、空信号和有效价格 |
| 结果看起来过好 | 时间戳、未来数据、价格复权、费用与挑选参数过程 |
| 找不到输出 | 看本次 YAML；相对路径以 YAML 所在目录为基准 |

阅读源码顺序：先 `docs/learning/first_factor.py`，再 ALPHA101 的 YAML 和 Python，接着 `betalens-factor/factor_template.py`，最后按问题定位分组、回测和统计函数。没有必要从头读完全部因子。
