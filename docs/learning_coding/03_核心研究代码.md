# 03：核心研究代码怎么读

[导航](README.md) · 文件级明细：[Datafeed](generated/core_datafeed.md)、[Factor](generated/core_factor.md)、[Backtest](generated/core_backtest.md)、[Analyst](generated/core_analyst.md)

## 1. Datafeed：门面、SQL 和连接池

从 `betalens/datafeed/core.py` 的 Datafeed 开始。它验证逻辑数据集，借出只读连接和 cursor，再将查询转给 `query.py`。业务代码通常不需要自己拼 SQL。

`query.py` 有规范化 schema 与旧结构分支。registry 定义逻辑表如何映射物理结构/核心指标；`industry.py` 和 `universe.py` 处理 PIT 专项查询。`pool.py` 管理全局池与线程安全，`config.py` 管理配置来源，`validation.py` 处理检查和修复。

```python
from betalens.datafeed import Datafeed

# 需要真实数据库；with 负责释放借出的连接。
with Datafeed("daily_market") as feed:
    frame = feed.query_time_range(
        codes=["000001.SZ"], start_date="2024-01-01",
        end_date="2024-01-31", metric="收盘价(元)",
    )
```

输入是明确代码/指标/范围，输出是查询表。不要把 `with` 理解为无连接开销；构造已建立资源。资源泄漏常表现为跑几次正常、重复执行后连接池耗尽。

**修改切入点。** 日期匹配问题先看 query；成分错误先看 universe 与入库生效记录；字段别名先看 registry；不要用在业务算子里补日期的方式掩盖底层查询错误。新增查询需检查 before/after 方向、区间包含、容差单位、空结果、新旧结构分支以及连接归还。

## 2. Factor：从长表到标签和权重

`factor.py` 混合了取数辅助与纯分组函数，不能把整个模块都当纯计算。先读这四个入口：

1. `get_tradable_pool`：交易日期 → 正常/指定状态的候选代码，需要 trade_status。
2. `pre_query_characteristic_data`：日期、指标、代码范围 → 分组前长表，默认查询基本面表。
3. `single_characteristic`：长表 → `(input_ts,code)` 标签表，不需要真实数据库。
4. `get_single_factor_weight`：标签和规则 → 权重宽表，也能离线运行。

双特征和多特征不是简单把分数组合相加：独立排序分别分组后取交集，条件排序先分主特征，再在组内分次特征。顺序因此可能改变样本。

**必须保留的细节。** `equal_count` 保证目标组数，平分时用代码稳定排序；`value` 不拆相同值，实际组数可能减少。`max/min` 选择器解决实际标签数变化问题。输出 attrs 中的分组模式/目标组数也可能被下游读取，不只需要保留列值。

## 3. Preprocessing、Profiling、Stats 的分工

| 文件 | 主要输入 | 主要输出 | 不应混淆 |
| --- | --- | --- | --- |
| preprocessing.py | 当期分数、行业和市值 | 处理后分数、残差、诊断 | 开启中性化不保证每期实际执行 |
| profiling.py | 因子值历史 | 覆盖、分布、异常、自相关等 | 因子值体检不证明未来预测有效 |
| stats.py | 分数与正确对齐的未来收益 | IC、回归、分组和择时评价 | 函数不会自动修好错误的收益标签 |

`neutralize_factor` 会在样本不足时跳过并返回原分数，所以要检查 `skipped`。`calc_ic` 对每期至少要求五只共同有效股票，样本不足为 NaN。当前 `calc_icir` 的均值/标准差比值未自动年化。

如果“报告突然没有 IC”，先核对日期、代码交集和有效样本，不要第一时间修改相关系数算法。若预处理后样本丢失，检查 merge 键、控制变量缺失及中性化跳过条件。

## 4. 通用 FactorPipeline：真正的编排中心

文件在 `betalens-factor/factor_template.py`，不在 Python 主包目录。这是新手容易找错的位置。

`FactorSpec` 保存 name、inputs、compute、compute_kwargs、PIT/行业/市值和权重设定；`run()` 接收日期、调仓频率、组数、资金、输出目录等。主要流程：

```text
交易日历 → 预热范围 → 信号日前一交易日
→ PIT 成分并集 → 行情宽表对齐 → 算子
→ 信号日长表 → PIT 过滤 → 可选预处理
→ 分组 → factor_values/体检 → 权重
→ 执行时间 → BacktestBase → Analyst/图表/dump → RunResult
```

`RunResult` 还支持旧的 `bt, analyst = result` 解包，但完整结果有 profiling、neutralize_stats、factor_values、pit_validation 等信息。新增返回信息时，应检查兼容解包以及 Dashboard 消费路径。

当前行业/市值开关控制一整段预处理，改变开关不只影响最后一次回归。经典多空当前固定高组多低组空，direction 字段没有在该路径中实现文档所称反转。维护时应补证据和回归用例，而不是修改文案后假定行为变了。

## 5. BacktestBase：按状态理解大类

文件 `betalens/backtest/backtest.py` 较长。按状态形成顺序读，比逐行读有效：

| 阶段 | 输入 | 主要结果 |
| --- | --- | --- |
| 构造/输入校验 | 权重、资金、参数 | 类型标准化、属性初始化 |
| `get_trade_status` | 代码和日期/预载状态 | 状态面板与审计信息 |
| `get_rebalance_data` | 目标时点与价格指标 | cost_price、actual_datetime、cost_ret |
| `get_position_data` | 当期资产、权重、匹配价格 | actual_weight、资产递推、交易记录等 |
| `get_daily_position_data` | 实际持仓、日行情 | 日频持仓价值、损益、nav |
| `dump_to_excel` | 已计算实例属性 | 多 sheet Excel 文件 |

构造函数调用上述主要计算，因此 `bt = BacktestBase(...)` 已经跑了回测，不存在必须再调用一个通用 `bt.run()` 的步骤。

输入目标权重不是最终组合。默认 lot_size=100，股数向零截断，余款进入现金；下一期资产用上一期实际权重和收益递推。`actual_datetime` 用于核对真正匹配到哪个价格时间；权重时间戳本身不保证成交。

`rebalance_log` 应按其实际交易行结构理解，不要假设每个输入调仓日必然有一笔成交。单股票全仓且无需调整的预载例只有首次交易。

**离线理解方式。** 运行研究课程第13课：`python docs/learning/labs.py 13`。它向真实引擎注入内存价格并关闭状态查询，能核对1000股与净值，不证明停牌、节假日或现实撮合正确。

## 6. Analyst：计算、展示和文件导出的边界

`metrics.py` 负责纯指标；`plotting.py` 负责图形；`naming.py` 查名称并缓存；`analyst.py` 的 Analyst 门面组合这些能力，同时保留 PortfolioAnalyzer/ReportExporter 兼容入口。

优先用 `Analyst.from_backtest(bt)`，它提取 actual_weight、日持仓价值、损益和交易明细。只有 nav 时部分持仓/交易指标无法计算，应该缺省或跳过而不是伪造零。

修改一个指标要核对其输入频率、分母、符号、空值、基准对齐，以及 Dashboard 是否又计算了同名指标。当前 annualized_return 用净值点数作年化指数分母，max_drawdown 返回正的回撤幅度；这些都属于需明确的当前口径。

## 7. EventStudy 与 Robust

事件模块按标准交易日构造窗口，返回 daily_stats、holding_stats、returns_matrix、price_matrix 等，并可扩展多资产 comparison。事件 ID、相对日和缺失窗口必须保持，不能把有效行压紧导致事件错位。

`robust/__init__.py` 公开的是 `robust.py` 内的 RobustTest；`newrobust.py` 是另一个实现，文件名不能决定实际生效入口。旧版构造时将联合删缺失后的 X 上一行与 y 下一行配对，因此不等同同日联合多因子回归。`.work()` 等旧入口的调用参数还需额外审查。

初次接手优先能复核分组和回测，再碰这类统计与历史兼容代码。修改后不只看是否报错，更要证明计算问题没有被改写。
