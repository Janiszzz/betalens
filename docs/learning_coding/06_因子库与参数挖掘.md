# 06：具体因子、公共模板和参数挖掘

[导航](README.md) · [Alpha101 逐项索引](generated/alpha101_catalog.md) · [其他因子和模板](generated/factor_catalog_and_templates.md)

## 1. 大量同名脚本为何存在

一个具体因子通常有 `.py` 和同名 `.yaml`。YAML 保存完整实验参数；Python 声明算子、配置转换和命令入口。公共流程集中在模板中，因此修改一段模板可能影响很多因子。

当前 Alpha101 有101个截面脚本及101个择时脚本，每个有对应 YAML，共404文件。不要要求新同事先背完这些包装代码：先读 ALPHA101 这一简单例子，再读公共模板和公式注册表，最后按编号定位差异。

## 2. 具体脚本的接口解剖

| 符号 | 输入 | 输出/用途 |
| --- | --- | --- |
| `load_config(path)` | 完整 YAML | 配置字典，校验必需分节 |
| `compute_*` | `inputs` 对应的具名宽表与公式参数 | 因子值宽表或该策略定义的结果 |
| `build_spec(config,config_path)` | 配置和路径 | FactorSpec |
| `spec` | 默认配置加载 | 模块级实验定义；不是运行结果 |
| `run_from_config(path)` | 运行配置路径 | 管线 RunResult/产物 |
| `main()` | `--config` | 执行一次运行 |

Dashboard 依赖模块暴露 `spec`、`FactorPipeline` 和 `build_spec`，因此重命名这些接口要同步加载端。import 允许读取默认 YAML，但不应启动回测和写结果。

`if __name__ == '__main__'` 把直接运行与模块加载隔开。为了“方便调试”把 main 调用搬到模块顶层，会让因子详情查询也触发回测。

## 3. 完整 YAML 的四个分节

| 分节 | 角色 | 消费者 |
| --- | --- | --- |
| meta | 类名、因子名、来源、公式、策略类型 | 因子发现和界面 |
| factor_spec | 输入指标、公式参数、PIT/控制/价格设置 | factor_spec_options/build_spec |
| weight | mode、long_groups、short_groups及分配 | 权重生成 |
| run | 区间、频率、组数、资金、导出路径 | run_parameters/FactorPipeline.run |

类级 YAML 用于发现类别和元信息，不能假定缺少的因子运行参数会被类默认值自动补上。Dashboard 会把页面提交合并成一份完整 run_config，再从同一份配置构造 spec 和 run kwargs。

`output_dir` 是相对 YAML 所在目录解析的。配置副本移动到另一个目录后，输出也可能移动；这不是代码随机写错位置。

## 4. Alpha101 的真正计算位置

- `alpha101_formulas.py`：公式定义、所需输入与历史需求。先在这里找编号对应公式。
- `factor_template_alpha101.py`：常用算子及截面/择时桥接。`rank` 在同日股票间排序，`ts_rank` 沿同股历史窗口排序。
- `alpha101_parameters.py`：从参数类型和边界规则生成搜索定义。
- `alpha101_mining.py`：向通用挖掘器提供 MiningSpec。
- 各 ALPHA 目录：包装脚本和可运行完整配置。

公式改动时至少检查输入依赖、滚动窗口/滞后累计历史、广播维度、缺失处理、零分母、单位与行业语义。历史需求不足可能让起始窗口无效，但不能通过填未来值来补齐。

**生成工具现状。** 现有文档提到 `alpha101/tools/generate_catalog.py`，当前仓库没有该文件。不要照着文档执行这个不存在的命令，也不要在交接中宣称已验证自动生成一致性。若要恢复生成流程，需要明确源码真源、生成规范和检查方法；当前先按注册表与现有包装逐项核对。

## 5. 其他因子类别

TDX 类模板封装通达信风格算子，注意平滑与窗口定义；LiqDemand 类为流动性需求研究封装算子和管线；DISP 还具有自己的挖掘入口；ILLIQ_v2 等具体因子应按配置查看输入字段和历史需求。

不要因为类名含“高频”就认定当前输入一定是逐笔或分钟数据，实际输入频率要看脚本、表、指标和源数据。逐文件索引给出具名函数签名，可从 `compute_*` 与输入配置开始核对。

## 6. 新增因子的最短完整路线

先学习 `docs/learning/templates/research/COURSE_MOM` 的完整教学实现：它已经包含算子、配置和 CLI。新增自己的类别/因子目录时满足 `DEVELOPMENT_RULES.md` 的命名规则，在已有目录中不要覆盖他人的实验。

完成以下检查：公式玩具样本可手算；配置能构建 spec；import 不启动回测；发现接口能列出；少量真实数据可以走完整管线；输出路径和报告可追溯。课程模板是教学起点，不代表新公式已经通过研究有效性检验。

## 7. Mining 分层

```text
两份完整 YAML
 → run_mining / 配置校验
 → 因子 hook: make_mining_spec(params)
 → 数据获取 + PIT/历史需求 + 缓存
 → 候选采样 + 窗口评价
 → 汇总/细搜/扩边/扰动
 → ResultStore 与审计/热力图
```

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| mining.py | 配置、MiningSpec、数据窗口 | MiningResult/逐候选评价 |
| mining_optuna.py | 参数分布、历史结果、搜索规则 | 候选、study、扩边和扰动计划 |
| mining_cache.py | 数据面板、PIT、输入指纹 | 只读 memmap、manifest、切片 |
| mining_audit.py | 候选/窗口/状态 | 结果 SQLite、metadata、审计 Excel、热力图 |

`precomputed` 与 `rolling_fit` 的差异关系到是否每个窗口单独拟合。把需要训练的算法错误地按全区间预计算，会改变统计设计。缓存签名不能只含因子名字，还应反映真正输入；失效策略要与更新数据的方式一起审查。

当前 total 热力图汇总 evaluation.span，不是自动标记过的独立测试集。参数扰动稳定也不是跨时期稳定。维护代码时应保留失败候选和审计状态，不能只为了图表漂亮删除失败记录。

## 8. 修改影响范围示例

把一个 `correlation_window` 默认值从10改20：可能影响公式默认签名、具体 YAML、历史需求、自动搜索边界、已有配置兼容和缓存指纹。仅改包装脚本的函数默认值，而 YAML 仍传10，运行行为可能完全没变。

先在输入到 compute 的 kwargs 打断点确认生效值，再决定应该更新哪个真源。修改后同时比较配置解析结果和算子数值。
