# 09：常见维护改动怎样落地

[导航](README.md) · [变更记录模板](templates/变更记录模板.md)

本章给出实施路径，不会自动改动业务代码。每次先确认需求是否改变研究定义，再动手。

## 场景 A：给一个因子增加参数

例：新增 `window` 或阈值。

1. 写清数学定义、类型、合法范围与默认值，并准备能手算的输入。
2. 修改具体 compute 或公式注册表，明确具名参数。
3. 更新完整 YAML 的 compute_kwargs；如果参数影响历史需求，同步 required_history_bars 推导。
4. 确认 build_spec 实际把参数传进去，不能只看界面出现输入框。
5. 检查 Dashboard `_build_run_config`、因子详情和保存的 run_config。
6. 若用于 mining，同步参数生成规则、合法边界与缓存签名。
7. 测默认值兼容、边界值、改变参数确实改变预期输出、历史不足不使用未来数据。

完成证据：一份完整配置、一次算子输入输出、一段运行日志/实际kwargs、相应验证。

## 场景 B：新增一个绩效指标

例：某种持仓集中度。

1. 明确输入是目标权重还是实际权重，现金是否计入，多空按净权重还是绝对权重处理。
2. 在 metrics.py 实现纯计算，用一组可手算持仓验证。
3. 如需 Excel 报告，接入 analyst.py 的汇总/分组，而非只在页面计算。
4. 如果 Dashboard 需要，接 serialization 的 metrics 数据及其格式标记。
5. 同步 types.ts 与 App 的分组、单位和空值展示。
6. 对无持仓数据的 nav-only 结果设计明确缺省，不伪造为零。

完成证据：同一案例在低层计算、报告和前端 JSON 中值与单位一致。

## 场景 C：接入新的指标或数据来源

先区分“新数据源但已有指标”和“新逻辑数据集/物理结构”。前者可能只需 adapter 和字段映射；后者可能影响两个 registry、contract、migration、writer、query 与兼容视图。

1. 定义来源格式、单位、可知时间和唯一键。
2. 使用适配器输出标准 ImportBatch，拒绝行保留原因。
3. 让 preview 和 run 走同一解释规则，继续使用文件哈希与 token。
4. 新指标映射检查核心行情列与普通 observation 的区别。
5. 需要 schema 时新增 migration，并同步 verify 契约。
6. 在隔离库验证写入、重复导入、冲突处理、事务回滚和 Datafeed 读回一致性。

完成证据：源样本 → 标准批次 → 数据库 → Datafeed 的同记录往返核验；若任一步时点/单位变化要有解释。

## 场景 D：修复回测收益不符合预期

1. 固定代码/配置/输入版本，保存异常日期和持仓。
2. 列出目标权重、实际权重、价格时间、股数、现金与日损益。
3. 用单股票或两股票预载价格复现，排除 DB/前端影响。
4. 找第一次数值分叉，不要直接修改最终 nav 公式让曲线接近预期。
5. 检查状态处理、整数手、前一期持仓收益、日期对齐和缺价处理。
6. 为实际缺陷增加边界案例，再验证正常买入持有基线仍正确。

完成证据：修改前后第一处分叉的解释与回归结果。仅“最终收益率好看了”不合格。

## 场景 E：页面参数保存了却没生效

按字段流逐点查看：React 表单值 → api.ts 请求 JSON → Pydantic RunRequest → runs._build_run_config → run_config.yaml → factor_spec_options/run_parameters → build_spec → compute/run 的真实参数。

先确认参数属于公式参数、spec 参数还是 run 参数。放错分节可能被忽略；把 null、空字符串、字符串数字当成相同值也会改变行为。

完成证据：同一值在所有边界的记录；覆盖旧配置默认值、显式值和非法值，验证错误在合适的边界报告。

## 场景 F：给明细表加一列/一个筛选

1. 确定源对象确实有该信息，不从展示文本反推。
2. 更新 serialization 建表和 Parquet schema/写入记录。
3. 确认分页过滤、排序、空值和日期格式仍一致。
4. 更新类型和表格列定义，筛选变化重置页码。
5. 检查旧缓存是否缺列，明确兼容/重建策略。

完成证据：第一页/后续页、筛选无结果、有空值与大表的合理行为。

## 提交前统一检查

使用变更记录模板说明触发条件、旧行为、新行为、影响模块、验证、未验证部分和兼容性。更新必要的正文说明；运行源码索引生成器检查接口是否过期。没有修改数据库/线上服务的需求时，不要顺带执行这些动作。
