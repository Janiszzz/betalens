## 1. 开发环境验收

在仓库根目录选择正确的 Python。新建虚拟环境前先确认是否已有；本节提供命令，不自动替用户安装：

```powershell
python -c "import sys; print(sys.executable); print(sys.version)"
python -m pip install -e ".[full,test,docs]"
python -m pip check
python -c "from betalens.analyst import Analyst; from dashboard.backend.main import app; print('imports OK')"
```

`full` 没有包含 test/docs，需要显式安装对应 extras。第一次研究课程检查曾发现完整 Analyst 缺 `prettytable`；这提醒我们不能只检查轻量 `import betalens`。本次没有修改 Python 环境。

后端：`python -m uvicorn dashboard.backend.main:app --host 127.0.0.1 --port 8000 --reload`。

前端：进入 dashboard/frontend 后运行 npm install（或满足锁文件条件时 npm ci），再 npm run dev。启动插件可能自动启动后端。前端 build：`npm run build`。

## 3. 当前代码与文档差异

| 证据位置 | 当前观察 | 对维护的影响 |
| --- | --- | --- |
| factor_template.py `_resolve_groups` | 经典模式固定 max/min，未用 direction 反转 | 修改方向需明确策略与回归用例 |
| backtest.py `ftc/ptc` 引用 | 保存/导出，未见用于净值扣费 | 不可宣称设置非零就已扣费 |
| metrics.py annualized_return | 年化指数分母是 len(nav) | 与区间数口径可能不同，变更会影响历史报告 |
| robust/__init__.py | 导出 robust.py 而非 newrobust.py | 新文件名不代表已切换实现 |
| robust.py `work` 等旧入口 | 有与当前 bootstrap_once 签名不一致的调用 | 使用前审阅；不要当新人首个稳定范例 |
| docs/guide/factor-pipeline.rst | 引用了缺失的 alpha101/tools/generate_catalog.py | 当前无法执行所写目录生成检查 |
| test_factor_yaml.py + .gitignore | 测试要求 XICHOU，但该类被忽略，本地目录也不存在 | 新克隆不能满足这部分 fixture 预期 |
| adapters/files.py | 读取 CSV/XLS/XLSX | Parquet 依赖存在不证明该入口支持 Parquet |
| frontend/api.ts | 通用重试也覆盖 POST | 重复任务需幂等与错误场景设计 |
| backend/runs.py clear | 取消排队并重建线程池，不能强杀运行线程 | 清理不等于立即停止计算 |
| .github/workflows/publish.yml | release 后构建发布，没有测试步骤 | 发布成功不等于业务测试通过 |

这里是已核对执行路径/文件存在性的交接记录，不是本次修复清单；核心代码未被更改。每个问题应分别评估影响、设计回归测试，再实施修复，避免顺手改变研究口径。

## 4. 常见故障的最短排查链

| 现象 | 先看 | 再看 |
| --- | --- | --- |
| 导入时报模块缺失 | sys.executable、pip环境、完整 import | pyproject extras/可选依赖 |
| health=ok但回测失败 | 任务日志和 Datafeed 连接 | schema、数据日期/字段 |
| 股票池为空 | PIT 成分快照和交易状态锚点 | code格式、公开/生效时间 |
| 分组不足 | 中性化前后样本、有效因子数 | equal_count/value 契约 |
| 权重正确而收益异常 | actual_datetime/actual_weight/position | 复权、缺价、实际成交对齐 |
| 表格空页 | query/filters与page组合 | Parquet、serialization、TS字段 |
| UI 参数没生效 | run_config.yaml | _build_run_config、run_parameters、compute_kwargs |
| 任务清理后仍占资源 | 运行线程与旧executor | 取消设计、后台dump与查库 |
| 导入预览后执行被拒绝 | 文件哈希/preview token | options/目标/写入模式是否改变 |

保留最小失败样本和完整异常尾部。不要默认删缓存、清数据库或重新安装所有依赖；这些操作可能抹掉定位证据。

## 5. 验证分层

第一层：纯函数/数据契约测试；第二层：预载价格回测与 mock 序列化；第三层：隔离测试库验证读写、迁移、回滚；第四层：本地浏览器端到端；第五层：适用的构建与发布检查。

修一个纯格式问题不必跑大规模挖掘；改价格匹配则必须有跨节假日、缺价及时间戳相关用例。验证应解决具体风险，不用测试数量代替问题覆盖。

## 6. Git 与发布

当前历史使用中文提交说明；分支可用 `codex/具体主题` 或团队要求的名称。先查看 git status，避免包含他人文件。提交描述写问题、最终行为与验证结果。

发布 workflow 由 release.published 触发，使用 PyPI trusted publishing。发 release 是外部发布动作，不能作为新人随手测试构建的方法。本课程不创建发布、不推送远程、不修改数据库。
