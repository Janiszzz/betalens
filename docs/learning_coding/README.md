# Betalens 新程序员维护交接手册

这份手册面向刚接手维护的程序员。目标是理解数据怎样流动、代码在哪里负责什么、修改会影响谁，以及怎样验证修改没有改变研究口径。

研究员课程在 `docs/learning/`；本目录 `docs/learning_coding/` 关注实现、接口和维护。业务背景不足时，先完成研究员课程第 02、03、04、13 课，再读这里。

## 两条阅读路线

**第一天快速定位：** 先读架构地图、数据契约、维护与测试，再运行已有离线例子。遇到一个具体文件时，到逐文件索引查职责和接口。

**系统接手：** 按下表顺序，每读一章就画调用链或复核一份输入输出。最后用第一月任务完成一次小型改动。

## 逐文件索引包含什么

本次静态扫描覆盖 **544 个 Git 跟踪的源码/配置文件**，提取 **2592 个 Python 类、函数、方法及内部函数声明**。其中 Alpha101 的 101 个截面和 101 个择时脚本连同 YAML 共 404 个文件，均可逐个定位。声明数量不等于公共 API 数量。

每个文件列出作用、文件级输入、输出、副作用和维护重点；Python 接口表列出具体名称、源码行、参数、默认值、返回注解或 return 表达式线索、原 docstring 摘要。完整 docstring、返回表达式和调用线索保存在 [inventory.json](generated/inventory.json)。未声明返回类型的函数不会被自动猜成某个确定类型。

TypeScript 的顶层声明采用正则定位，完整 props/类型需阅读源码与第 05 章；SQL 文件列出实际操作位置。锁文件、数据、构建产物、忽略的本地配置不作为源码逐项展开。

| [AI 协作说明示例](templates/CLAUDE.md.example) | 已核对的项目约定 | 可供新人参考的提示词，不改变仓库根目录指令 |

更新源码或新增文件后，先正常将拟纳入版本控制的源文件加入 Git 索引，再更新目录：

```powershell
python docs/learning_coding/build_catalog.py
python docs/learning_coding/build_catalog.py --check
```

生成器只读取 Git 文件清单和源码文本，不 import 项目、不连接数据库、不执行因子。`--check` 不写文件，检查索引是否与当前源码及人工说明一致。修改未跟踪文件不会进入索引，必须注意这条扫描边界。

## 维护者最先记住的五件事

1. 因子值、目标权重、实际持仓和净值是不同对象，不能混用。
2. `Datafeed` 构造会获取连接；`BacktestBase` 构造会执行回测。它们不是无副作用的数据容器。
3. 研究读层、数据库写层、UI 展示层的职责分开；不要在取数接口里塞入文件导入。
4. 时间戳、单位、PIT 和缺失值语义是接口的一部分，不是可以随便“清洗”的格式问题。
5. 写在 README 或 docstring 中的意图需要与执行代码核对；第 07 章记录当前发现的差异。

## 核验范围

文档按本地当前代码整理。静态目录生成不代表 544 个文件都做了运行测试。真实数据导入、数据库迁移、在线 Wind、完整市场回测、浏览器联调、参数挖掘及发布均未在本次交接中执行。已有核心测试的实际运行结果在本次交付说明中给出，未跑项目不预填成功。
