业务参考表：版本、发布与完整性
============================

``/integrity`` 工作台管理股票历史行业、交易日历和股票停牌区间。
三个域新增独立版本表，保留旧数据，不改造行情、财报或旧回测查询 API。
流程为：检查范围 → 从缺口登记请求 → 拉取和日志 → 缓存审计 → 确认追加 →
核验发布 → 再次检查或撤销发布。

任务可信与业务完整
------------------

任务可信指某目标库、模块及明确范围完成提数、追加、读回核验和发布。
业务完整指所问日期、行业归属或停牌时刻是否有明确解释；可信响应也可包含业务未知或冲突。
未知继续返回，并附原因、任务及版本来源，不将未知转换成休市、无停牌或正常交易。

PG/CH 分别判断可信，同一任务的 ``calendar``、``industry``、``suspension`` 分别发布。
PG 发布而 CH 失败时 PG 数据可用；已发布行业也不会因其他模块失败而失效。
任务总状态、SQLite 日志或两库行数一致均不能替代目标库发布凭证。

物理表与可见性
--------------

.. list-table:: 新增业务版本表
   :header-rows: 1
   :widths: 47 53

   * - 表名
     - 粒度及主要字段
   * - ``stock_industry_membership_versions``
     - 股票 × 体系 × 层级完整历史快照中的一个有效区间；分类版本、行业代码和名称、有效起止及边界依据。
   * - ``trade_calendar_versions``
     - 交易所 × 自然日；开市标志、上一交易日、参考交易所及日历依据。
   * - ``stock_suspension_intervals_versions``
     - 股票 × 日期完整事件集中的一个事件或解析区间；停复牌类型、原始时段、UTC 起止、整日标志及解析状态。

共用物理键为 ``(revision_id, scope_id, record_id)``，业务键另行登记。
行中保留 ``import_task_id``、``attempt_id``、``revision_id``、来源、哈希、映射及结构版本：

* ``event_date``：业务发生日期。
* ``available_at``：实际可得时间；无证据时为 NULL。
* ``downloaded_at``：下载时间。
* ``ingested_at``：该目标库本批次实际写入时间。
* ``ingestion_seq``：目标锁内单调分配的入库顺序，不依赖时钟是否回拨。

每个目标库还保存三张不可变元数据表：

* ``reference_revision``：任务、尝试、模块、入库序号及版本清单。
* ``reference_scope``：范围选择条件、完整标志、行数、键和内容哈希；允许零行范围。
* ``reference_publication_event``：``publish``、``revoke`` 事件及撤销任务编号。

数据追加后先不可见，核验行数、键、内容及范围证明后才发布。
PG 用事务及目标锁；CH 在受控窗口和目标锁下分步追加、核验，最后写入发布事件。
CH 物理排序键包含修订，合并不会抹掉旧版本。

业务读取先筛已发布且未撤销修订，再按 ``ingestion_seq`` 选范围最新版本，读取其完整记录集。
不能先对全部物理行取最新，也不能逐列拼接不同修订。新快照 NULL 不继承旧值，
未发布新行不遮住旧可信解释。直接 SQL 查询版本表含未发布和已撤销记录，不能当业务有效数据。

三个域的检查规则
----------------

股票历史行业
~~~~~~~~~~~~

来源为申万 ``index_member_all``、``index_classify``，中信 ``ci_index_member``。
支持 ``SW2021``、``SW2014``、``CITICS`` 及 1—3 级；权限不足明确报告。
历史提数需要当前、历史成员的完整证据，不能把仅 ``is_new=Y`` 当作完整历史。
申万成员接口不能按分类版本直接过滤，处理器保留与所选版本字典匹配的依据；
不匹配或边界不明不能伪造分类版本和历史归属。

发布范围是“股票 × 体系 × 层级”的完整历史快照。
日期查询先取范围最新可信快照，再按有效期定位，而不是只筛 ``valid_from`` 落入查询窗口的行。
行业代码或生效日期修订时整个快照替代旧解释，旧错误区间不会因业务键不同而残留；
撤销新快照后恢复此前未撤销的可信快照。

内部区间为 ``[valid_from, valid_to)``。无法证明源端边界时保留依据并返回未知，
不猜测纳入、剔除日归属。同日重叠返回冲突，历史缺口或边界不明返回未知。

交易日历
~~~~~~~~

范围为“交易所 × 自然日”，包括开市和休市，逐自然日检查。
缺日返回未知，不能当休市。分别登记 SSE、SZSE、BSE；当前 BSE 使用 SSE 参考日历，明确保存
``reference_exchange='SSE'`` 及 ``calendar_basis``，不伪装为 BSE 原生响应。

股票停牌区间
~~~~~~~~~~~~

``suspend_d`` 提供事件，日历和股票上市、退市范围提供依赖证据。
一天可有多个日内区间，完整空响应也保存无事件范围凭证。
只有事件查询完整、日历明确开市、股票在上市范围内，零事件才可解释为
``no_reported_suspension``（未报告停牌）；它不等于所有交易限制均通过。

原始时段按 ``Asia/Shanghai`` 解释，以 UTC 存储，区间 ``[start_at, end_at)``。
原始字符串保留；完整起止、整日事件和多区间分别处理。
仅有复牌标记无法证明时刻、无法解析、未知边界或事件矛盾均返回未知或冲突，不猜测复牌时刻。
只判断指定时刻是否处于停牌区间，不处理午休、集合竞价、撮合或其他交易限制。

默认采用最新可信修订的历史事实。业务有效期与入库时间分离，未知 ``available_at`` 保留 NULL，
不宣称已实现严格历史可知性回测数据。

网页操作
--------

#. 选择目标库、模块、股票、日期、交易所、行业体系及层级；停牌可填多个上海本地检查时刻。
#. 检查逐范围数据、完整状态、未知原因及版本来源，从单条缺口或整次检查生成请求草案。
#. 核对实际请求、依赖及分钟上限，登记参考任务；登记本身不发网络请求。
#. 开始拉取，查看实时日志与执行尝试；完成后数据库仍未写入。
#. 审计原始值、标准化区间、范围证明、拒收原因和 before/after。
#. 确认后追加并发布。存在不完整范围时可显式仅发布通过范围，其余保留原因。
#. 分别查看每库、每模块结果并重新检查，必要时撤销本任务发布。

“预览参考表建表计划”只新增上述六张表，确认后执行。同名物理结构不符会阻断，不静默重建。
版本查询默认显示可信当前数据；审计模式可看全部修订、不可信记录、范围、发布和撤销事件。

确认绑定缓存、归档、结构和转换合同、目标及审计时版本头。
审计后其他任务修改同范围，必须重新审计，过期令牌不能直接发布。
中断保留记录与尝试，未发布修订仍不可信；“建立关联的新版本任务”后重新拉取、审计和确认。
手工修改任务状态不能恢复可信，普通任务的 ``resume`` 也不能绕过参考域流程。

撤销生成新 ``rollback_task_id`` 并追加 ``revoke``，不删除历史业务行或原审计。
撤销当前修订恢复旧可信解释。修订中显式固定的发布依赖被撤销或变化时，检查报告依赖失效。
当前停牌范围通常以其归档中的日历、上市查询为独立证据，不依赖另一个未引用的日历任务；
不会仅因该任务撤销就丢弃完整的源查询证明。但当前可信日历与归档依据矛盾时，
返回 ``dependency_changed``，不能沿用原解释。

旧归档基线
----------

旧业务行不会自动成为可信基线，也不因旧任务完成或两库相同而获得发布资格。
“使用已有归档准备基线”按源任务编号比对来源身份、合同、请求、完整分页或分区证据及哈希。
匹配归档复制到新任务，证据不足范围列为待重新获取，仍需新审计和用户确认才能发布。
不自动启动历史全量补全。

HTTP 查询示例
-------------

``POST /api/integrity/check`` 仅检查，不创建更新任务，分别返回目标库数据、状态、原因及来源：

.. code-block:: bash

   curl -sS http://127.0.0.1:8010/api/integrity/check \
     -H 'Content-Type: application/json' \
     --data '{"targets":["postgres","clickhouse"],"modules":["calendar","industry","suspension"],"security_codes":["000001.SZ"],"start_date":"2026-10-12","end_date":"2026-10-14","exchanges":["SSE","SZSE","BSE"],"schemes":["SW2021","CITICS"],"levels":[1,2,3],"check_times":["10:00:00"]}'

必须给出明确起止日期，行业及停牌必须指定股票，不能隐式查询全市场。
未知字段和无效范围被拒绝；用 ``source_id`` 指定来源，不在请求中携带 Token。

``GET /api/reference/versions?target=postgres`` 返回可信快照，``audit=true`` 返回全部审计版本。
``GET /api/reference/tables`` 查询版本表的两库部署与覆盖。
任务接口位于 ``/api/reference/tasks``，与普通表接口并存；完整清单见 :doc:`../api/infra`。
普通 CLI ``query`` 不支持这些参考版本表，应使用专用 HTTP 检查接口。

不能用 ``COUNT(*)``、最大业务日期、任务状态或同日其他股票的数据代替范围证明。
结果区分未请求、失败、权限不足、待确认、未发布、中断、已撤销、源无记录和业务未知等原因。
调用方需保留未知及原因，不能静默转换成完整覆盖。
