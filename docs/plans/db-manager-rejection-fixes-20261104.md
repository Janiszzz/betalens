# DB Manager 拒收原因与修复（2026-11-04）

任务 `93142cda35b744d193a5388f7c780762` 于北京时间 11:19 结束，状态 partial：211 个转换批组中 66 个成功、145 个失败，共记录 91,969 条拒收条目。单条拒收使整个批组等待处理，因此失败批组数不等于错误记录占比。

## 原因与修复

| 原因 | 实测证据 | 修复 |
| --- | --- | --- |
| 把全球指数成分当成境内证券代码 | 单一原因批组中至少 86,086 条因此拒收；原始数据包括 `00700.HK`、`BABA`、`6758`、`035720`、`5PD` | 仅对 `index_membership.security_code` 使用源成分标识规则，原样保留大小写约束下的合法标识和前导零，不猜测市场、不补后缀。其他证券表仍执行境内后缀校验。 |
| 分红预案尚无公告日 | 单一原因批组中至少 376 条“源数据业务主键为空”；原文为“股东提议”“预披露”等且 `ann_date=NULL` | 允许分红源公告日为空。`dividend_event` 继续用内容版本键保存观察记录，可得时间保持未知；只有满足原实施条件的记录才生成实际公司行动。证券代码、报告期、实施进度仍须满足源键要求。 |
| 指数权重单日触顶无法再按日期拆分 | 41 个单一原因批组；129 个叶请求被阻断，部分响应恰为 7,000 行 | 新任务的单日查询改用运行时推进验证的分页，检查重叠并要求空页结束。真实请求 `000013.CSI / 20261030` 返回 5,000＋2,389＋0 行，无交叠，证明原 7,000 行响应确实漏了记录。 |
| 行业完整证券拆分超过旧阈值 | 全市场证券清单 5,926 个，旧阈值 2,000；行业快照出现四个覆盖/缺档问题 | 两个行业接口的新策略允许最多 12,000 个基于完整源清单的证券分区，保持 Y/N 范围、账户限频和有界派发；不从截断响应推导证券清单。 |

前两项数量是保守下界：旧缓存只保存前 100 个拒收样例，混合原因批组无法据此精确分摊。新版转换结果保存完整原因计数 `reject_summary`，审计接口通过 `reason_counts` 返回，样例继续有界。

## 同时完成的热点优化

行情及派生表共用一次来源转换；表定义、映射执行计划在单批内复用；L0 不生成可选逐字段血缘；本次读取内复用已验证类型结果和哈希。归档 SHA、固定镜像、竞争检查和写后全字段核验继续执行。

同一真实日期批组 8 表、152,658 行，全部输出哈希一致，纯转换耗时由 143.7379 秒降到 36.2612 秒。5,000 行写前条件核验三次中位数由 0.5027 秒降至 0.2096 秒，结果哈希相同。均为局部测量，不代表端到端加速比例。
