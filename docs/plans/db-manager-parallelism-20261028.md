# DB Manager 并行优化计划与验收

范围限定独立 DB Manager，使用当前 5000 积分限频策略。保留普通业务表与参考域可信发布的边界。

| 环节 | 现状 | 本轮优化 |
| --- | --- | --- |
| 网络与转换 | 已有下载线程池、转换进程池和积压水位 | 保留限频、内存预算和有序提交；不重复叠加并发 |
| 普通入库 | PostgreSQL、ClickHouse 已各有单写入通道 | 保留每库顺序和业务键冲突检查 |
| 人工审计预览 | 两库依次检查结构、读旧值、生成冻结镜像 | 两库各一条有界并行通道，单库内顺序处理 |
| 人工放行与修补提交 | 两库依次安装冻结意图并写入 | 两库独立并行；某库失败仍等待并记录另一库结果，重试沿用原回执 |
| 回退 | 两库的批次混在同一串行循环 | 两库独立并行；每库严格逆序，保留镜像和后续修改保护 |
| 事后校验 | 每批依次读取与检查两库 | 每批两库并行，报告按固定顺序合并；来源重放和跨批依赖保持原顺序 |
| 双库核验、结束覆盖刷新 | 两库依次读归档、刷新覆盖 | 两库有界并行，失败分库记录 |
| 控制元数据与审计同步 | 单条读回执、逐回执镜像 | SQLite 批量读取，脏回执每包最多 128 条；只确认已镜像的修订 |

不能并行打乱的步骤：同一库中有覆盖关系的写入、同一库的逆序回退、ClickHouse 受控写窗口、分页后继及来源依赖、写入前的持久化意图。SQLite 仍使用短事务单写，不按行启动线程。

验收包括：双库确实同时推进；一库失败时另一库完成且原意图可重试；重叠记录逆序恢复；单库回退与后续另一库回退状态准确；来源/任务上下文不串用；审计同步失败和进行中修订不误确认；原生 PG/CH 与浏览器回归。只使用临时数据库和本地来源，不重跑生产导入或回退。实际加速以受控对照测试报告为准，不承诺整体任务固定倍数。

已实现上述并行与批量读取路径，并增加分库阶段耗时和失败日志。普通写入、来源合同及其固定参数不变。参考域可信发布流程保持原有实现。

只读对照（2026-10-28，同一旧任务、各两次采样中位数）：804 条回执由 805 次连接降到 1 次，约 0.238 秒降到 0.0057 秒，约 42 倍；335 条阶段记录由 336 次连接降到 1 次，约 0.107 秒降到 0.013 秒，约 8 倍。两个各包含 0.3 秒独立等待的通道，由串行 0.601 秒降到并行 0.301 秒；该项仅验证等待重叠，不代表生产端到端耗时。原始数据见 `/tmp/betalens-parallel-benchmark-20261028.json`。

验收结果：完整后端收集 478 项，465 项直接通过、1 项离线归档基准按开关跳过。12 项旧夹具因默认 ClickHouse 用户未配置而初始化失败；使用私有环境文件路径重跑整个旧管线测试文件，29 项全部通过，因此所有 477 项可运行测试均已通过。新增并行与恢复测试 8 项、相关浏览器验收 11 项通过。测试没有调用 Tushare 下载接口；数据库写入仅发生在隔离测试库。
