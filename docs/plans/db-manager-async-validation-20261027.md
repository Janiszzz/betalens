# DB Manager 异步采集、分级校验与 5000 积分请求优化计划

日期：2026-10-27；实施更新：2026-10-28。状态：异步管线、分级校验和请求优化已实现，已通过隔离验收；历史生产采集保持停止。

## 1. 目标与已确定的行为

- 覆盖独立 `betalens-db-manager/` 已登记的 31 个 Tushare 接口、普通业务表及日历/行业/停牌参考域，不修改研究包 `betalens/`。
- 用户已选择：默认轻量校验通过后自动异步入库；关闭网页后已显式启动的任务继续后台运行。
- 网络下载优先。下载、标准化、两库写入、可选深度校验分别调度，不让完整预览/业务校验阻塞下一次 API 请求。
- 默认只运行数据包轻量检查及必要的存储一致性保障。业务值、时间先后、跨表勾稽、完整读回与逐列来源审计默认关闭，可在任务结束后按表、证券、日期、目标库运行。
- 默认仍为 `fill_missing`，`refresh_source` 必须由任务显式指定。旧任务、已暂停/取消/回退任务不自动迁移或启动；自动定时任务仍默认关闭。服务进程重启后保存中断状态，用户显式恢复后从检查点继续。
- 不改变普通表业务主键、数值精度、UTC 存储及北京时间显示口径；本轮不重构稠密/稀疏交易状态等业务存储语义。

## 2. 执行管线与校验分层

### 调度和持久化

```mermaid
flowchart LR
    A[任务计划与共享限速] --> B[并发 HTTP 下载]
    B --> C[轻量检查与不可变原始归档]
    C --> D[持久化待处理队列]
    D --> E[转换一次并缓存 Parquet]
    E --> F[PG 写入队列]
    E --> G[CH 写入队列]
    F --> H[批次存储核验与回执]
    G --> H
    H --> I[任务完成或部分完成]
    I -. 按需或用户预选 .-> J[业务值与勾稽校验任务]
```

- 保留单状态目录执行器，扩展为持久化阶段队列和租约，不引入 Redis/Celery。SQLite 只保存任务、分片、批次、租约和文件清单等元数据，大型数据及前后镜像存为不可变文件。
- 默认 8 个下载线程，每个线程独立 HTTP Session 和请求上下文；2 个转换进程；PG、CH 各 1 个写入通道。两库可以并行，单库内重叠表/键范围按任务创建顺序、批次序号执行；失败范围的后续重叠写入暂停，不阻塞其他目标库及无依赖的下载。
- 下载线程只持有响应包，不执行业务规则或数据库差异预览。原始十进制词法值保留，不先转浮点再转 Decimal；转换进程负责一次性的类型、单位、日期、复权及派生处理。
- 原始响应原子归档后才确认下载分片；标准化缓存按原始 SHA、映射/处理器版本、表定义版本和输出范围寻址。预览、提交、重试及后续校验复用缓存，不再次生成同一标准化结果。
- 复用现有 Arrow 能力，将 `pyarrow` 纳入新管线运行依赖。Parquet 保持 Decimal(38,12)、日期及带 UTC 语义的时间类型。
- 一个网络响应不等于一个入库批次。每个目标表累积到 5 万行、未压缩 64 MiB 或等待 10 秒即形成批次；剩余数据在下载/依赖完成时立即排空。参考域以证据完整的范围快照为发布单位，传输块可以更大，不能把不完整范围发布为完整。
- 同一任务内精确相同的源请求只下载一次，可服务多个目标表和两库。跨任务仅在明确指定旧归档/来源快照时复用，避免把旧快照冒充新采集。
- 默认本地处理内存预算 4 GiB；未消费归档积压超过 20 GiB 暂停新请求，降至 10 GiB 后继续。磁盘剩余低于 10 GiB 时暂停并保留检查点，清理后显式恢复。慢入库不会通过无限内存排队拖垮下载。

### 用户可选的校验

| 层级 | 默认 | 内容与执行时机 |
| --- | --- | --- |
| L0 数据包轻量检查 | 开启，固定 | HTTP/API 状态、JSON 结构、字段名与必需键、行宽、归档 SHA、用于分页/分区的证券和日期范围、分页交叠及饱和响应处理；收到每包即检查，不运行行情/财报业务规则。 |
| L1 单表业务值 | 关闭，可勾选 | 行情 OHLC 关系、负成交量、复权因子有效性、日期区间冲突等。可预选任务结束后运行，也可事后指定范围。 |
| L2 跨表与时间关系 | 关闭，可勾选 | 原价×复权因子与后复权价关系、行情与日历/上市区间关系、行业版本和有效区间、同口径同版本的资产=负债+权益等勾稽；检查公告/可得时间证据。 |
| L3 完整存储与来源审计 | 关闭，可勾选 | 完整读回、逐行逐列来源证据和严格两库对照；替代当前每次提交都无条件执行的昂贵审计。 |

- L1—L3 可独立选择。面板显示适用表、预计扫描量和依赖，不把未执行显示为通过。
- 入库固定保障独立于可选业务规则：类型可表示、主键有效、同键歧义处理、写入竞争保护、持久化回退镜像、受影响批次的键集合及值一致性核验。用户选择轻量档也保留这些保障。
- 转换错误或坏包隔离对应分片，继续下载其他合法分片；依赖不完整的派生批次等待或标为部分完成，不补造正常状态。任务总状态不能掩盖未入库分片。
- 事后校验独立生成带规则版本、数据范围及快照指纹的报告，结果为通过/失败/未知/不适用；数据之后发生变化则报告过期。缺证据不判通过，不自动修复、覆盖或回退数据。
- 业务规则显式声明适用字段、报表/资产类型、单位及容差。金融勾稽默认绝对容差为该源披露精度的一单位、相对容差 1e-6，取较大者；输入精度不明则未知。历史修订与源端时间依据不足不宣称严格 PIT 或已证明因果。

## 3. 5000 积分请求策略与大分块

### 共享调度规则

- 账户档位固定为用户确认的 5000；常规接口官方档位为 500 次/分钟，程序总速率默认 450 次/分钟。共享限速覆盖同订阅的线程、进程、任务和重试，不对每个线程分别放行 450 次。
- 显式接口低限额优先，例如 `stock_basic` 官方 50 次/分钟；该接口默认也不超过 50。对于文档只说明更高积分拥有更高频次、未公布 5000 档具体频次的 ETF 两接口，先使用 50 次/分钟保护值，只有获得明确额度证据后才更新，不能把 8000 档的 500 次直接套用。
- HTTP 429 遵守 Retry-After；分钟限频至少冷却 60 秒并将受影响限速降为原值一半，最低 10 次/分钟；连续 5 个完整分钟无再次限频后每分钟恢复原上限的 10%，不超过已确认的档位/接口上限。仅明确属于账户范围的限制才暂停整个订阅。
- 网络/5xx 单请求最多 4 次尝试，指数退避并加抖动；持续失败后分片保留为待重试，不拖垮其他接口。日/小时配额不足暂停相应范围，权限不足标记不可用，不重复空转或当作空数据。
- 将最低积分、独立权限、官方行数上限、运行观测值、保护阈值、分页能力、完整拆分维度、文档 URL 和核对日期登记为版本化能力策略，并冻结到任务计划。旧任务保持旧快照。
- 请求规划比较“少量证券的长历史”与“全市场按日期”的预估请求数。目标接近单次上限的 90%，允许不可再细分但低于硬上限的合法包；不生成不必要的证券×交易日笛卡尔积。
- 命中上限继续拆分；有已确认分页能力时以实际返回行数推进，直至空页，短页不直接判完成。父响应只保留证据，不与子分区重复入库；分页不受支持或无法证明覆盖时明确阻断受影响范围。

## 4. 提交核验、审计与接口改动

### 消除本地重复开销

- 表定义、类型转换计划、字段规则和 schema hash 每个冻结版本只构建一次；每行只规范化一次，主键哈希仅处理主键列，不反复转换整行。
- 按选定源绑定和生产依赖执行转换，消除管理层与旧派生层对同一响应的重复标准化。后复权任务若显式选择 `daily` 和 `adj_factor`，不再无条件补拉 `daily_basic`；未请求的估值列标记为未获取，已有非空值按写入模式保留。选择 `daily_basic` 的任务仍完整采集该接口。
- PG 用 COPY 到批次暂存表并集合合并，CH 用较大数据块写入。两库分别从固定来源缓存和各自真实 before 值形成 after-images，保持 `fill_missing`/`refresh_source` 语义。
- 提交时在受影响键/分区内用数据库集合比较目标值与冻结 after-images，检查键集合和差异行数；不以行数相同代替值一致，也不把两库不同原生哈希算法直接比较。严格逐列 Python 读回移到 L3。
- 两库各自完成存储核验后，对其规范化 after-images 做列式业务值对照；已有非空值不同导致的差异明确标记，不能在 `fill_missing` 下偷偷覆盖。
- 精确 before/after 镜像在写库前持久化到批次 Parquet，SQLite 和两库保存批次清单及摘要。默认不再把完整逐行 JSON 审计反复全量镜像；现有分页审计 API 由新日志按需展开，L3 可生成完整逐行/逐列报告。
- 审计同步使用带确认水位的增量 outbox；回退日志、标准化缓存和原始归档固定保留到用户显式清理。缺少回退必需镜像时不能继续破坏性清理。
- 覆盖统计改为受影响证券/日期/分区增量更新并合并刷新；任务末尾做一次汇总，全表重算仅作为显式维护动作。
- 新任务回退从批次镜像流式恢复，PG 使用集合逆操作，CH 只重建受影响分区并保留发布前检查与恢复凭据；仍检查当前值是否等于本任务 after 值，保护后续修改。

### 状态、失败与兼容

- 分别记录下载完成、转换完成、各目标写入、存储核验、审计同步和业务校验状态。任务完成默认指选中目标的存储核验完成；业务校验尚未运行显示“未执行”。
- 分片/批次使用稳定 ID 和租约；进程在落盘、写库、提交、回执之间退出后，恢复先核验已应用范围，不重下成功归档、不盲目重复写入。
- PG 和 CH 故障分别保留待恢复队列，其他目标可继续。目标发生未预期变化时停止该范围并标记待协调，不覆盖固定提交意图。取消后立即停止派发新请求，当前请求/数据库安全边界结束后保存检查点；已提交部分保留。
- 参考域继续使用不可变修订、范围完整性、核验后发布与 revoke 回退；传输大块不能削弱其可见性规则。业务校验状态与可信发布/请求完整性分开显示。
- 新管线使用 `pipeline_version=2`，旧任务没有该字段时沿原路径，原有归档、审计和回退可读；只新增控制元数据迁移，不因升级自动变更业务表值。

### 公共接口与页面

- 保留现有编译和建任务入口；新任务增加 `pipeline_version`、`auto_commit`、`run_in_background`、`validation_profile`、`post_check_rules`，默认分别为 2、true、true、light、空列表。并发、批次及缓冲默认值放设置页高级选项，编译时冻结。
- 新增 `POST /api/tasks/{job}/start` 启动新管线；原 download/preview/commit 命令仍保留其明确含义，不能把旧 download 调用静默改成自动写库。
- 新增 `POST /api/tasks/{job}/validations` 创建事后校验任务，允许指定规则、目标、表和导入范围内的证券/日期；提供分页结果查询和导出。默认使用当前目标数据并标明对应快照，原始归档可供严格复核。
- CLI 增加 `run JOB`、`validate JOB --rules ...`；已有 cancel/resume/rollback 按版本路由。
- 页面增加轻量默认预设、L1—L3 勾选、任务结束后运行选项及“追加校验”入口。分别显示网络吞吐、下载/处理积压、两库完成量、限频冷却与下载/本地处理 ETA，不把请求配额时间当作端到端时间。
- 网页会话只影响控制台连接，不再终止显式后台任务；保留暂停/恢复/取消控制。新执行器统一管理 GUI、CLI，替代依赖临时 tmux 脚本的正式工作流。

## 5. 实施顺序、测试与验收

按以下顺序交付，每阶段通过对应测试后进入下一阶段：

1. **策略和基线**：完成 31 接口的能力配置及公式化请求量预估，记录每个保护值的证据；用已归档样本测量现有校验、提交、审计、覆盖统计耗时。
2. **持久化异步管线**：实现分阶段队列、连接复用、共享限速、原始归档、转换缓存和后台生命周期，先接通无生产写入的完整演练。
3. **批量提交和可恢复审计**：接入 PG/CH 写入通道、批次前后镜像、集合核验、增量审计和覆盖统计；贯通取消、恢复、重叠任务及回退。
4. **可选校验与界面**：实现 L1—L3 独立任务、数据快照/规则版本报告、API/CLI/GUI 配置和阶段进度，覆盖参考域。
5. **隔离库验收与灰度**：先归档重放、再隔离 PG/CH/本地 HTTP 来源，最后用用户明确指定的全新小范围任务验证。不会自行恢复已停止或回退的生产采集。

必须覆盖的测试：

- 31 接口策略均有配置；50/450 等共享限速在多线程、多进程、多任务及重试时不超预算；429、日配额、权限错误和不同订阅隔离。
- 恰好满页、隐藏短页上限、空页终止、重复/交叠页、分区覆盖、分页失效回退；完整清单包含所需退市证券和 E/O 基金，不依赖残缺本地维表。
- 默认轻量档不执行 OHLC、财报勾稽和逐列来源循环；坏包仍被隔离。后加校验能发现预置错误，缺依赖为未知，数据变更后报告过期。
- 标准化结果与旧流程的相同行为输入逐字段一致；每个有效缓存键只构建一次；数值精度、原价×因子、公告/报告期过滤和 UTC/北京时间口径不回退。
- 下载期间故意阻塞业务校验或一个数据库，另一阶段仍持续前进；积压触发磁盘/内存保护；关闭网页后台继续，服务中断保持可恢复状态。
- 写库前后各检查点故障注入、单库失败、重叠区间、重复恢复、回退保护；原有旧任务继续可查询和回退，新审计 API 展开结果与镜像一致。
- 下载和深度校验不得隐式更改已有业务值；参考域未发布/被撤销/证据不足范围不出现为可信完整数据。

性能门槛：

- 在本机相同数据库规模、索引、相同归档及同等回退保障下，对“五个交易日”样本运行三次取中位数；默认轻量档的本地校验与双库提交总耗时至少较当前流程缩短 3 倍，目标不超过 60 秒。默认路径没有每行 schema hash 计算、每批全表覆盖重算及重复标准化。
- 使用可控延迟的本地 HTTP 来源验证下载调度：不存在配额、网络、磁盘积压限制时，达到所配置速率的至少 90%；深度校验不应使下载阶段退化为串行等待。
- 分别报告下载耗时、转换耗时、两库写入/核验耗时、审计同步耗时、峰值内存和磁盘增量。正式全量耗时通过新管线实测重新估算，不沿用旧流程的 2—4 天，也不承诺仅用理论 API 分钟数完成全部入库。

完成标准：三个用户目标均可在 GUI/CLI 复现，默认后台自动异步入库、可事后追加业务校验、31 接口策略与 5000 档证据对应，且故障恢复、重复任务与完整回退全部通过隔离验收。

## 6. 2026-10-28 实施记录

已接通新任务的后台下载、独立进程转换、类型化 Parquet 缓存、双库独立批量写入、原生集合值核验、持久化批次镜像与增量清单同步。新增 `import_batch_receipt` 是控制元数据；在首次新管线写入时建立，不修改业务表合同。旧任务沿原路径，旧归档和回退记录保留。

网页普通表及参考域均可选择新管线和 L1—L3；API/CLI 支持启动、恢复、追加校验、范围筛选及报告导出。默认不运行可选业务校验。分页审计按需读取镜像；后续管理器写入或回退会保守标记相关表的报告过期。直接绕过管理器的数据库修改需重新执行校验以识别，报告指纹不构成后台持续监控。

参考域仍保留范围完整性、不可变修订、核验后发布与撤销流程；其本地发布阶段以完整范围为单位，不拆成不完整小块发布。它的请求与业务可信依据检查仍是发布门槛，不能通过关闭可选业务规则绕过。

普通表就绪批次立即派发，不主动等满 10 秒；上限为 50,000 行/64 MiB。当前转换以依赖齐全的月份、单证券历史或快照为单位，单批包检查完成并不意味着对应派生数据已经可写入。积压按未消费原始归档压缩字节统计；Linux 转换进程监视内存预算，超限停止子进程并保留归档，可缩小范围后重建任务。

财报勾稽仅在同口径权益、版本和源披露精度都有依据时判定。当前内置宽表没有独立权益列，归档可辅助定位；未提供披露精度的来源输出“未知”，不推断为通过。
