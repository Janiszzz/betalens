# 转换批次性能优化记录

2026-11-04 17:30（北京时间）已部署。实现标识：`mapping-hoist-date-cache-20261104`。

## 原因与已实施方案

| 方案 | 实现 | 保留的校验 |
| --- | --- | --- |
| 映射版本哈希移出逐行循环 | 修复 `mapping.get('version', digest(mapping))` 的默认参数提前求值；已有版本号直接复用，没有版本号时每个映射/来源批次只计算一次 | 映射快照验证、记录版本号、源记录哈希不变 |
| 跳过空投影的字段转换 | 轻量转换时，派生表尚未生成、没有行可补充的映射不再逐行执行；有输出的表和明细表照常转换 | 保留派生表生成、完整证据重放、数值精度和拒收规则 |
| 日期解析与有界复用 | `YYYYMMDD` 通过 `date` 构造验证；复用日期对象，字符串解析结果使用最多 8,192 项的进程内 LRU | 非法月份、日期、闰年及非标准数字仍拒收；缓存不保存异常 |

剖析样本中，`digest` 累计占 84.5 秒剖析耗时中的 52.3 秒。尤其第一项会为每行序列化整份映射，即使版本号已经存在。此次直接消除这项重复工作，保持 3 个转换进程及已有 PG/CH/管理器共享约 90% WSL 资源的预算。
