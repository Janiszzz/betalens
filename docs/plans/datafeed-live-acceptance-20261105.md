# Datafeed 真实数据库验收（2026-11-05）

数据库已经完成建表和本次入库，但**尚不能完整支持严格 PIT 业务查询**。新版 Datafeed 能连接 PG/CH，已测调用的返回结构、dtype、缺失值和错误类型一致；目前可直接使用的是当前展示名称查询。行情、历史名称、参考域及指数成分仍受历史可得性或完整范围证据限制，财报尚无数据。

## 双库结构与时间核对

41 张表的名称及字段名称集合一致，验收涉及的 18 张表逻辑字段类型一致。管理控制表另有 5 个存储类型差异：`import_task.request`、`import_batch_receipt.manifest/result`、`import_row_audit.before_value/after_value` 在 PG 为 JSON、CH 为字符串。它们不参与本次业务 DataFrame 返回；报告保留这些差异，没有把全库原生类型描述为完全相同。

PG 返回的带时区时间与 CH 返回的 UTC 存储时间，经归一后对应同一时刻。例如 PG 的 `2026-11-04 00:00+08:00` 对应 CH 的 `2026-11-03 16:00 UTC`。没有通过固定加减八小时改写数据库值。

因有效 PIT 行情为零，本轮不能据空结果宣称已用真实数据验证公告前后、非空价格的容差/端点、修订切换或复权因子历史可知性。这些仍需补齐证据后复测。脚本的单次耗时仅作排查记录，不构成 SQL/Python 性能比较，也没有据此调整查询实现。

## 建议后续补齐事项

1. **行情的内容版本与真实可得时间**：补齐字段及复权因子的来源发布时间、对应内容版本和可追溯历史。不能把 `next_calendar_day_assumed` 批量改成可信标签，也不能把下载/入库时间当成历史公开时间；被覆盖的当前值不能恢复其历史修订顺序。
2. **参考域的正式版本发布**：通过三域独立流程生成、核验并发布范围、内容哈希与可得性证据。行业覆盖 SW 年份版本、三级及有效边界；日历覆盖逐自然日和 BSE 的参考依据；停牌包含可解析区间、完整零事件范围、上市及开市证据。普通更新任务未自动生成这些版本及发布元数据。
3. **指数完整快照**：按 Datafeed 当前合同补齐完整性字段及可信发布时间，保留对应内容版本、预期成员数和来源分页/范围证明。不能直接给全部现有记录填 `snapshot_complete=1`。
4. **财报覆盖范围**：本任务没有财报下载切片。当前管理器按报告期规划财报请求，2026-10-05 至 2026-11-03 不含季度末，因此没有生成报告期请求；这不表示期间没有财报公告。补数需明确如 `2026-09-30` 的报告期及公告观察范围，并保留公告、实际公告、报表类型、修订可得时间等证据。指标口径不能用 TTM 代替报告期。
5. **历史名称与缺因子基金**：补历史名称内容版本的真实公开证据，检查 `158008.OF` 的复权因子来源与可适用性。证据不足继续保留缺失。
6. **单位与精度**：发布库内字段单位、精度等声明，和实际列定义、来源转换规则核对后再验收。当前不按列名猜单位，也不补造元数据。

以上是后续数据库与数据合同工作清单，本轮未执行导入、DDL 或标签修复。

也可使用 `BETALENS_DATAFEED_TEST_CONFIG` 指向包含双库连接的新版订阅 JSON。`--task` 仅供显式指定了 manager env 的情况读取其 SQLite，只读打开，不构造会维护状态的服务实例。

脚本保留本次任务的日期与代表代码，以便复现；扩大验收范围时修改 `cases()` 中的明确请求。退出码 `0` 代表已测代表性查询有值且自动检查完成，`1` 代表额外执行失败或业务合同不一致，`2` 代表无额外执行错误但数据/证据门槛未满足；`0` 也不代替全量覆盖和历史修订验收。
