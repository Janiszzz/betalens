# DB Manager 阿里云配置与价格方案

查询日期：2026-11-05（北京时间）。偏好：性能接近现有环境、优先稳定。估价范围：中国内地杭州、Linux x86、全年运行，迁移管理器、PostgreSQL、ClickHouse 和审计/回退证据；不含因子挖掘或 GPU 计算。

## 推荐部署

选择一台 `ecs.g9i.4xlarge`（16 vCPU / 64 GiB），管理器可沿用 systemd，PostgreSQL 16 和 ClickHouse 25.8 沿用 Docker Compose。服务器提供计算资源，容器组织数据库的部署，二者可以组合使用。

| 项目 | 推荐配置 |
| --- | --- |
| 地域 | 华东 1（杭州），实际可用区按库存选择 |
| 系统 | Ubuntu 24.04 LTS x86_64 或相容 Linux；重新安装组件虚拟环境 |
| 计算 | g9i 16 vCPU / 64 GiB；g8i 同规格可作为备选 |
| 系统盘 | 80 GiB ESSD PL1 |
| 持久数据盘 | 500 GiB ESSD PL1，保存 PG、CH、SQLite、归档和回退镜像 |
| 公网 | ECS 固定公网 IPv4，按使用流量计费，带宽峰值先选 100 Mbps |
| 备份预算 | 同地域 OSS 标准 LRS，平均保留 200 GB |
| 服务访问 | 优先 SSH 隧道访问本地管理端口；公开入口另配 HTTPS 和身份认证 |
| 资源预算 | 保留约 10% 系统余量；上线先沿用已验证的 3 个转换进程、12 个下载线程，再根据压测重配三服务上限 |

本机为 Ryzen 5 7500F，12 个逻辑 CPU，WSL 约 47 GiB 内存。现有内存上限 PG 14 GiB、CH 20 GiB、管理器 8 GiB，合计 42 GiB；这是上限，不是实测峰值。巡检时三者合计实际内存约 6 GiB，不能据此断言 8 GiB 或 16 GiB 云机可以承接批量任务。

存储巡检：管理器状态目录约 104 GiB，其中 pipeline 约 90 GiB、SQLite 约 11 GiB、原始归档约 3.8 GiB；PG 业务库 6,274,579,479 字节，CH 活跃业务数据 604,499,297 字节。现有持久数据合计约 110 GiB，500 GiB 用于保留增长、WAL、CH 合并和恢复空间。90 GiB pipeline 中包含回退证据，不作为可随意删除的临时目录。

g9i 的选择依据是现代 x86 处理器和通用型实例定位，而不是承诺按 vCPU 数等比例提速。本机 CPU、云 CPU 和云盘延迟不同，最终以相同真实归档的转换/写入/读回压测验收。[官方规格](https://help.aliyun.com/zh/ecs/user-guide/general-purpose-instance-families/)。

## 官网报价与完整预算

从用户提供的[官方定价页](https://www.aliyun.com/price/detail?saleProductCode=ecs)对应公开只读接口取得杭州、Linux、x86 的 `general_discount_price`。未使用账户专属合同、优惠券或无法核实的首购活动。公开价目表不保证特定可用区库存。

三档使用相同的 80 GiB + 500 GiB PL1 云盘、200 GB OSS 备份及每月 50 GB 公网出网假设：

| 方案 | 实例 | CPU/内存年费 | 计算及云盘年付 | 含假设备份/出网的全年估算 | 年付折算每月 |
| --- | --- | ---: | ---: | ---: | ---: |
| 降配参考 | u2a，8 vCPU / 32 GiB | ¥6,612.48 | ¥12,528.48 | ¥13,296.48 | ¥1,108.04 |
| 平衡 | u2a，16 vCPU / 64 GiB | ¥13,224.96 | ¥19,140.96 | ¥19,908.96 | ¥1,659.08 |
| **推荐** | **g9i，16 vCPU / 64 GiB** | **¥16,034.05** | **¥21,950.05** | **¥22,718.05** | **¥1,893.17** |
| 同级备选 | g8i，16 vCPU / 64 GiB | ¥15,672.38 | ¥21,588.38 | ¥22,356.38 | ¥1,863.03 |

推荐方案计算如下：

- 计算实例一年：16,034.05 元。
- 80 GiB 系统盘：80 × 10.2 = 816 元/年。
- 500 GiB 数据盘：500 × 10.2 = 5,100 元/年。
- OSS 存储预算：200 GB × 0.12 元/GB/月 × 12 = 288 元/年。
- 出网流量预算：50 GB/月 × 0.8 元/GB × 12 = 480 元/年。
- 合计：22,718.05 元/年，即年付折算 1,893.17 元/月。建议实际预算留到 2,000 元/月。

官方 PL1 报价有适用实例条件：g9i/u2a 使用一年 10.2 元/GiB 的档位。另有一年 7.2 元/GiB 的促销行，适用指定 u1/e 等实例，不套用于本方案。[云盘计费规则](https://help.aliyun.com/zh/ecs/block-storage-devices)。

**折月值不是逐月购买的价格。** g9i 16/64 单独月付为 1,908.82 元/月；两块 PL1 盘月付合计 580 元，再加本方案 64 元/月的 OSS/出网假设，逐月购买约 **2,552.82 元/月**。可以短期按量或月付压测，再决定年付；不要把一年费用折月当成可按该数逐月续费。

12/48 并非一定便宜：本次查到 u1 12/48 计算年费 15,552 元，整套估算 22,236 元/年，反而高于 u2a 16/64，故不选作省钱方案。8/32 则需要将现有 42 GiB 内存限额下调，并减少转换并行，属于性能降配。

## 带宽、备份与存储增长

ECS 的下载响应属于入网，固定公网 IPv4 模式仅出网流量计费。官方杭州公开出网价为 0.8 元/GB，本估算未抵扣 CDT 免费额度。若将云数据库的大量行情结果下载回本地做研究，这属于出网：100 GB 约 80 元，1,000 GB 约 800 元，按实际用量替换预算。[公网计费](https://help.aliyun.com/zh/ecs/public-bandwidth)。

100 Mbps 是按量网络的峰值上限，不是持续带宽承诺，也不能直接等同于接口请求速度。若后续需要更高或有保障的吞吐，单独比较 EIP/固定带宽，不能只看流量单价。

OSS 的 0.12 元/GB/月为官方标准 LRS 存储参考，200 GB 只是平均备份保有量假设。OSS 请求、取回、额外云盘快照、域名、负载均衡和 Tushare 订阅费用未包含。公网上传备份与同地域内网访问应区分计费。[OSS 计费](https://help.aliyun.com/zh/oss/storage-fees)。

PL1 数据盘若从 500 GiB 扩至 1,000 GiB，在相同年付单价下增加约 5,100 元/年，即 425 元/月。现阶段无需为日频数据库直接购买多 TB，但大范围重建任务或分钟数据需要重新估算。

## ECS、ECI 与 ACK

ECS + Compose 最贴近当前运行模型：SQLite、本地文件路径、文件锁和双库写入编排仍保持单机，不增加分布式状态管理。

[ECI 官方按 vCPU/内存计费](https://help.aliyun.com/zh/eci/product-overview/elastic-container-instances/)的标准公开单价为 CPU 0.1764 元/vCPU/小时、内存 0.022068 元/GiB/小时。以 730 小时/月估算：

| 计算规格 | ECI 仅计算月费 |
| --- | ---: |
| 12 vCPU / 48 GiB | ¥2,318.53 |
| 16 vCPU / 64 GiB | ¥3,091.37 |

以上未含持久化、公网等费用，且按申请量计费，低 CPU 使用率不会自动按比例减价。ECI 的经济型、节省计划和指定 ECS 规格可有不同价格，故这些数值不代表所有 ECI 组合。当前 24 小时驻留、状态与数据库同机的需求优先 ECS；未来可再把可独立执行的短时转换任务拆到弹性容器。

[ACK Pro](https://help.aliyun.com/zh/ack/ack-managed-and-ack-dedicated/product-overview/cluster-management-fee)还收 0.64 元/小时的集群管理费，约 467.2 元/月，节点和云盘另计；ACK 基础版免管理费，但资源仍收费。现阶段一个节点的服务规模，集群编排收益有限。

## 迁移时必须保留的约定

1. 等待当前任务结束，进入维护并停止唯一写入端，取得 PG、CH、SQLite/归档/回执的一致性备份。保留原版本数据和可回退路径。
2. 固定原数据库版本与镜像摘要；在云主机恢复数据库、配置、私有环境、控制库及全部必要归档，再重建 Python 环境。
3. 当前任务记录包含绝对文件路径。优先保持原 Linux 路径；如重定位，需校验并迁移清单，不能仅复制业务数据库。
4. 目标指纹包含 PG/CH 地址和数据库名。管理器继续在同机使用相同 localhost 地址、端口、库名最省改动；改用容器服务名或托管数据库地址时，需受控处理指纹迁移，确保历史任务仍能审计和回退。
5. 当前 API 只信任 localhost，公开域名访问需调整可信入口并加认证。首期使用 SSH 隧道可保持现有访问约定，数据库端口限制在主机/私网。
6. 用真实归档复测转换耗时、双库读回、回退和恢复。验收后切换唯一写入端，原本地副本保留只读恢复用途。

这是一台云主机上的持久化与备份恢复方案。故障不停机需要另行设计多机/多可用区高可用，不能把多个容器视为多个故障域。
